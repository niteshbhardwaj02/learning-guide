Answer in 30 seconds

Use a fixed number of workers that claim the next item and store each result at its original index. Promise.all over every item creates no concurrency limit and can overwhelm a dependency.

Visual mental model · simplified
01Input queue
02At most N workers
03Results in input order

Production reasoning

The implementation below bounds active mapper calls and preserves ordering. It rejects on a mapper failure; already-running work is not automatically cancelled.

For a production import, decide whether to fail fast or collect per-item outcomes. Add a shared AbortSignal, a maximum input size and metrics for queue wait and execution time.

Trade-off

Bounded parallelism protects capacity, but a low limit may leave throughput unused. Tune against downstream latency and quotas.

JAVASCRIPT / INTERVIEW EXCERPT
async function mapLimit(items, limit, mapper) {
  if (!Number.isInteger(limit) || limit < 1)
    throw new RangeError('limit must be a positive integer');
  const results = new Array(items.length);
  let cursor = 0;
  async function worker() {
    while (cursor < items.length) {
      const i = cursor++;
      results[i] = await mapper(items[i], i);
    }
  }
  await Promise.all(Array.from(
    { length: Math.min(limit, items.length) }, worker));
  return results;
}

Answer in 30 seconds

Cancel the obsolete request when possible and make committing the result conditional on its request identity. Cancellation saves work; the identity check establishes which request may update the UI.

Visual mental model · simplified
01Query A starts
02Query B aborts A
03Only newest ID commits

Production reasoning

AbortController communicates cancellation only to operations that honor its signal. It does not undo a server-side mutation that already happened.

The example is a framework-independent latest-request-wins helper. HTTP failures must be checked explicitly because fetch does not reject merely because the server returned a 404 or 500.

JAVASCRIPT / INTERVIEW EXCERPT
function makeSearch(commit, reportError) {
  let generation = 0, controller;
  return async function search(query) {
    const id = ++generation;
    controller?.abort();
    const current = new AbortController();
    controller = current;
    try {
      const res = await fetch('/api/search?q=' +
        encodeURIComponent(query), { signal: current.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const data = await res.json();
      if (id === generation) commit(data);
    } catch (err) {
      if (!current.signal.aborted && id === generation)
        reportError(err);
    }
  };
}

Answer in 30 seconds

Debounce waits until a burst of calls becomes quiet. Throttle limits the rate at which calls run during a continuing burst. Choose based on whether you need the final intent or regular intermediate updates.

Visual mental model · simplified
01Many input events
02Reset quiet-period timer
03Invoke latest arguments

Production reasoning

For a search field, trailing debounce reduces unnecessary requests. For drag feedback, a throttled or animation-frame-driven update is often more appropriate.

Preserve the receiver and arguments, provide cancellation, and test rapid calls, no calls, unmount, and an exception thrown by the callback. Leading/trailing options and maxWait require additional state.

JAVASCRIPT / INTERVIEW EXCERPT
function debounce(fn, delayMs) {
  if (typeof fn !== 'function' ||
      !Number.isFinite(delayMs) || delayMs < 0)
    throw new TypeError('Invalid debounce arguments');
  let timer;
  function debounced(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = undefined;
      fn.apply(this, args);
    }, delayMs);
  }
  debounced.cancel = () => {
    clearTimeout(timer);
    timer = undefined;
  };
  return debounced;
}

TypeScript - Narrowing
Answer in 30 seconds

An LRU cache evicts the least recently used entry. For an interview implementation, use Map insertion order: a successful get moves the key to the end, and insertion evicts the oldest key when the capacity is exceeded.

Visual mental model · simplified
01Get refreshes recency
02Set appends newest
03Evict oldest over limit

Production reasoning

Test overwrite, repeated reads, undefined values, capacity one and invalid capacity. Do not confuse recency with frequency.

Map access is specified as sublinear on average rather than universally guaranteed O(1). Typical implementations make these operations effectively constant-time on average. Add byte budgets and expiration for production payloads.

JAVASCRIPT / INTERVIEW EXCERPT
class LRU {
  #items = new Map();
  constructor(capacity) {
    if (!Number.isInteger(capacity) || capacity < 1)
      throw new RangeError('Invalid capacity');
    this.capacity = capacity;
  }
  get(key) {
    if (!this.#items.has(key)) return undefined;
    const value = this.#items.get(key);
    this.#items.delete(key);
    this.#items.set(key, value);
    return value;
  }
  set(key, value) {
    this.#items.delete(key);
    this.#items.set(key, value);
    if (this.#items.size > this.capacity)
      this.#items.delete(this.#items.keys().next().value);
  }
}

Answer in 30 seconds

all requires all successes and rejects on a rejection; allSettled reports every outcome; race adopts the first settlement; any adopts the first fulfillment and rejects with AggregateError if all inputs reject.

Visual mental model · simplified
01Define success condition
02Choose combinator
03Cancel unnecessary work separately

Production reasoning

Choose all for independent required data, allSettled for a best-effort bulk report, race for choosing the first completed outcome, and any for redundant read candidates.

None of these methods cancels losing operations. Evaluate the cost and privacy implications of sending the same request to multiple providers. For an empty input, race stays pending, any rejects, and all/allSettled fulfill.

A practical preparation path

From recall to engineering judgment.

A suggested seven-session plan. Split or combine sessions around your interview date. Revisit weak answers rather than trying to memorize all 72.

Session 01 / JavaScript

Explain what actually runs.

Work through JS01-JS12. Predict execution order, implement the concurrency limiter and LRU, and test cancellation and stale responses.

Session 02 / React

Understand rendering and boundaries.

Work through R01-R14. Explain snapshots and effects first; then compare server/client boundaries, compiler optimization and the recent APIs.

Session 03 / Node.js

Make failure part of the design.

Work through N01-N12. Practice streams, idempotency, database races, rate limits, tracing and a graceful deployment.

Session 04 / React Native

Think beyond the JavaScript screen.

Work through RN01-RN10. Trace native boundaries, profile frame budgets, and design secure offline edits and compatible OTA updates.

Session 05 / AI Engineering

Make the model a bounded component.

Work through AI01-AI16. Draw an authorized RAG flow, tool-approval boundary, evaluation loop and cost budget. Practice reviewing AI-generated code.

Session 06 / System Design

Connect the complete product.

Work through S01-S08. State traffic assumptions, data invariants, failure recovery and a reversible rollout. Prepare truthful examples of your own leadership.

Session 07 / Rehearsal

Run a mixed mock. Repair the weak spots.

Start a mixed-track session, answer without reading, then self-rate. Rebuild one failed explanation with a diagram and an edge-case test. Rehearse a production incident and a migration decision from your own experience.

Optional capstone / design exercise

Design an AI support copilot.

A React web app and React Native app share a Node backend. Users can search tenant-scoped documents, stream cited answers, edit support notes offline and request an approved account action. Your design must handle stale data, cancellation, duplicate requests, provider failures and mobile updates.

Produce a component diagram, API and data contracts, one guarded tool flow, a failure/retry state machine, and a small evaluation set. Explain what you would intentionally leave out of the first release.
