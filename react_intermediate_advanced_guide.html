02FoundationsIntermediate

Render, commit and the state snapshot

A component is a calculation. A state update asks React to calculate again.

During render, React calls your component to work out the next UI. During commit, it applies the needed DOM changes. A re-render does not mean that every DOM element is replaced. Keep rendering pure: calculate JSX, but do not send requests, mutate props, or start subscriptions there.

A handler closes over values from the render that created it. Calling a setter does not rewrite those local variables. A functional updater is useful when the next value depends on queued previous state.

SnapshotCounter.jsx
import { useState } from 'react';
export default function SnapshotCounter() {
  const [count, setCount] = useState(0);
  function replaceThreeTimes() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
  }
  function incrementThreeTimes() {
    setCount(n => n + 1);
    setCount(n => n + 1);
    setCount(n => n + 1);
  }
  return <section>
    <output>{count}</output>
    <button onClick={replaceThreeTimes}>Replace three times</button>
    <button onClick={incrementThreeTimes}>Add three updates</button>
  </section>;
}

03FoundationsIntermediate

Design components with clear contracts

Prefer small, explicit component APIs to giant components with dozens of flags.

Think of props as inputs, callbacks as outputs, and children as a slot for content. Keep one owner for each piece of state. A controlled component receives its value from the parent; an uncontrolled input keeps its current value in the DOM. Pick an owner rather than maintaining duplicate values in both places.

TicketEditor.jsx
import { useState } from 'react';
function Panel({ title, actions, children }) {
  return <section aria-label={title}>
    <header><h2>{title}</h2>{actions}</header>
    {children}
  </section>;
}
function PrioritySelect({ value, onChange }) {
  return <label>Priority
    <select value={value} onChange={e => onChange(e.target.value)}>
      <option value="low">Low</option>
      <option value="high">High</option>
    </select>
  </label>;
}
export default function TicketEditor() {
  const [priority, setPriority] = useState('low');
  return <Panel title="Support ticket"
    actions={<button onClick={() => setPriority('low')}>Reset</button>}>
    <PrioritySelect value={priority} onChange={setPriority} />
    <p>Current priority: {priority}</p>
  </Panel>;
}

04FoundationsIntermediate

Keys, identity and state ownership

A stable key says which item is which, not where it happens to be today.

React associates state with a component position and type. Keys refine identity among siblings. Changing a key intentionally resets a subtree. Using list indexes for editable, reorderable rows can attach a draft to the wrong item. Random keys recreate rows on every render.

IdentityLab.jsx
import { useState } from 'react';
const initial = [{ id: 't-1', title: 'Login issue' },
                 { id: 't-2', title: 'Invoice issue' }];
function Row({ ticket }) {
  const [draft, setDraft] = useState(ticket.title);
  return <label>{ticket.id}
    <input value={draft} onChange={e => setDraft(e.target.value)} />
  </label>;
}
export default function IdentityLab() {
  const [tickets, setTickets] = useState(initial);
  const [revision, setRevision] = useState(0);
  return <section>
    <button onClick={() => setTickets(xs => [...xs].reverse())}>Reverse</button>
    <button onClick={() => setRevision(n => n + 1)}>Reset drafts</button>
    <div key={revision}>
      {tickets.map(ticket => <Row key={ticket.id} ticket={ticket} />)}
    </div>
  </section>;
}
Avoid accidental resets

Do not declare a component function inside another component if you expect its state to survive parent renders. Define it at module scope. useId is for accessibility relationships, not a substitute for data keys.

05FoundationsIntermediate

Hook rules and choosing the right tool

Hooks belong to React renders, not arbitrary utility calls.

Call ordinary Hooks at the top level of a function component or another Hook. Do not call them conditionally, in loops, in event handlers, or after a conditional return. React relies on consistent Hook order. Extract a component when a list item needs its own state. The use API is the special case: it can be conditional, but still belongs inside a component or Hook and not inside try/catch.

SafeConditional.jsx
import { useState } from 'react';
function Details() {
  const [draft, setDraft] = useState('');
  return <input aria-label="Draft" value={draft}
    onChange={e => setDraft(e.target.value)} />;
}
export default function SafeConditional() {
  const [open, setOpen] = useState(false);
  return <>
    <button onClick={() => setOpen(v => !v)}>Toggle details</button>
    {open && <Details />}
  </>;
}

06HooksIntermediate

useState / local state

Use it when a component needs to remember a value that affects its UI.

Think of state as a saved input to your next render. Replace arrays and objects rather than mutating them. An initializer function is useful when computing an initial value is expensive; it must be pure.

Signature
const [value, setValue] = useState(initialValue);
QuantityEditor.jsx
import { useState } from 'react';
export default function QuantityEditor() {
  const [order, setOrder] = useState({ quantity: 1, shipping: 'standard' });
  const total = order.quantity * 250;
  function add() {
    setOrder(old => ({ ...old, quantity: Math.min(10, old.quantity + 1) }));
  }
  return <section>
    <p>{order.quantity} items / Total: {total}</p>
    <button onClick={add}>Add one</button>
    <select aria-label="Shipping" value={order.shipping}
      onChange={e => setOrder(old => ({ ...old, shipping: e.target.value }))}>
      <option value="standard">Standard</option>
      <option value="express">Express</option>
    </select>
  </section>;
}

Read the code

The updater receives pending previous state. Spreading keeps shipping unchanged while replacing quantity. total is derived during render; it is not separate state.

Try a change

Add a Remove button with a minimum of one. Add an express shipping charge by deriving total, not by adding an Effect.

Common mistake

order.quantity++ mutates an existing snapshot. Also, useState(props.value) only initializes state; it does not stay synchronized with future prop changes.

07HooksIntermediate

useReducer / explicit state transitions

Use a reducer when related updates need clear, testable rules.

A reducer is a pure function: current state plus an action produces next state. Events describe what happened. Put requests, random ID creation and other side effects outside the reducer.

Signature
const [state, dispatch] = useReducer(reducer, initialState);
CartReducer.jsx
import { useReducer } from 'react';
export function cartReducer(state, action) {
  switch (action.type) {
    case 'added': {
      const old = state.find(x => x.id === action.item.id);
      return old
        ? state.map(x => x.id === old.id ? { ...x, qty: x.qty + 1 } : x)
        : [...state, { ...action.item, qty: 1 }];
    }
    case 'removed': return state.filter(x => x.id !== action.id);
    case 'cleared': return [];
    default: throw new Error('Unknown action: ' + action.type);
  }
}
export default function CartReducer() {
  const [items, dispatch] = useReducer(cartReducer, []);
  const total = items.reduce((sum, x) => sum + x.price * x.qty, 0);
  return <section>
    <button onClick={() => dispatch({ type: 'added',
      item: { id: 'book-1', title: 'React workbook', price: 300 } })}>
      Add workbook
    </button>
    <ul>{items.map(x => <li key={x.id}>
      {x.title} x {x.qty}
      <button onClick={() => dispatch({ type: 'removed', id: x.id })}>Remove</button>
    </li>)}</ul>
    <p>Total: {total}</p>
  </section>;
}

Read the code

The added branch handles a new item and an existing item. A stable dispatch function sends intent; the reducer owns update rules.

Try a change

Add a quantityChanged action. Reject invalid quantities in the reducer and test it without rendering React.

Common mistake

A reducer is not Redux, persistence, or a network layer. Mutating state inside it is still a bug.

useContext / shared dependencies

Read a value from the closest matching provider above your component.

Context avoids passing a prop through every intermediate component. It is useful for dependencies such as theme, locale or a service. A provider value change updates subscribed consumers; memo does not prevent that context update.

Signature
const value = useContext(SomeContext);
DensityContext.jsx
import { createContext, useContext, useState } from 'react';
const DensityContext = createContext(null);
function TicketList() {
  const density = useContext(DensityContext);
  if (density === null) throw new Error('Density provider is missing');
  return <ul style={{ lineHeight: density === 'compact' ? 1.3 : 2.2 }}>
    <li>Reset password</li><li>Check invoice</li>
  </ul>;
}
export default function DensityContextDemo() {
  const [density, setDensity] = useState('comfortable');
  return <DensityContext value={density}>
    <button onClick={() => setDensity(d =>
      d === 'compact' ? 'comfortable' : 'compact')}>Toggle density</button>
    <TicketList />
  </DensityContext>;
}

Read the code

createContext runs outside components. React 19 lets you render the context directly as its provider. TicketList reads the closest provider.

Try a change

Create a second context for locale. Explain which consumers should update when density changes.

Common mistake

A fresh object as provider value changes identity on every parent render. Split unrelated contexts and avoid putting every fast-changing value into one giant context.

Official reading: useContext

09HooksIntermediate

useRef / remember without rendering

Hold a DOM node or mutable handle that should not itself redraw the UI.

A ref is a stable container with a mutable current property. Change it from events or Effects. Do not use ref.current as hidden render state: React will not know that the screen needs updating.

Signature
const inputRef = useRef(null);
FocusSearch.jsx
import { useRef, useState } from 'react';
export default function FocusSearch() {
  const inputRef = useRef(null);
  const lastSaved = useRef('');
  const [message, setMessage] = useState('Nothing saved');
  function save() {
    lastSaved.current = inputRef.current.value;
    setMessage('Saved: ' + lastSaved.current);
  }
  return <section>
    <input ref={inputRef} aria-label="Search query" defaultValue="" />
    <button onClick={() => inputRef.current?.focus()}>Focus search</button>
    <button onClick={save}>Save current query</button>
    <p role="status">{message}</p>
  </section>;
}

Read the code

The DOM owns this uncontrolled input. An event reads it through the ref. State is used for the message because the message must re-render.

Try a change

Add a Restore button that writes the saved query to the uncontrolled input. Then rewrite the input as a controlled useState input and compare ownership.

Common mistake

Changing lastSaved.current alone would not update the paragraph. Do not read or write mutable refs during render, apart from a predictable one-time initialization pattern.

Official reading: useRef

10HooksIntermediate

useEffect / synchronize external systems

Use an Effect for a connection whose lifetime follows rendered state.

An Effect sets up synchronization after a commit. Its cleanup undoes the previous setup before a changed-dependency setup, and at unmount. List every reactive dependency. Effects run on the client, not during server rendering.

Signature
useEffect(() => { /* setup */ return () => { /* cleanup */ }; }, [deps]);
PollingClock.jsx
import { useEffect, useState } from 'react';
export default function PollingClock() {
  const [enabled, setEnabled] = useState(true);
  const [delay, setDelay] = useState(1000);
  const [ticks, setTicks] = useState(0);
  useEffect(() => {
    if (!enabled) return;
    const id = setInterval(() => setTicks(n => n + 1), delay);
    return () => clearInterval(id);
  }, [enabled, delay]);
  return <section>
    <p>{ticks} ticks</p>
    <button onClick={() => setEnabled(x => !x)}>{enabled ? 'Pause' : 'Resume'}</button>
    <select aria-label="Tick interval" value={delay}
      onChange={e => setDelay(Number(e.target.value))}>
      <option value={1000}>One second</option>
      <option value={300}>300 milliseconds</option>
    </select>
  </section>;
}

Read the code

Changing delay clears the old interval before starting a new one. The updater avoids capturing an old ticks value. Cleanup also makes the development Strict Mode setup/cleanup check safe.

Try a change

Pause the clock while the document is hidden. Add and remove the visibilitychange listener symmetrically.

Common mistake

An empty dependency list does not mean once forever. Mounts can repeat. An Effect callback must not be async because React needs its cleanup function, not a Promise. Define an async function inside it instead.

Official reading: useEffect

11HooksAdvanced

useLayoutEffect / measure before paint

Use it only when a layout measurement must affect the same visual frame.

This Effect runs after DOM changes but before the browser repaints. That can avoid a visible jump when positioning a tooltip. It blocks painting, so keep the work small. Prefer CSS when CSS can solve the layout.

Signature
useLayoutEffect(setup, dependencies);
MeasuredNote.jsx
import { useLayoutEffect, useRef, useState } from 'react';
function Note({ text }) {
  const ref = useRef(null);
  const [height, setHeight] = useState(0);
  useLayoutEffect(() => {
    setHeight(ref.current.getBoundingClientRect().height);
  }, [text]);
  return <div style={{ position: 'relative', marginTop: 100 }}>
    <button>Reference point</button>
    <div ref={ref} role="note" style={{ position: 'absolute',
      left: 0, top: -height - 8, width: 240, border: '1px solid', padding: 8 }}>
      {text}
    </div>
  </div>;
}
export default function MeasuredNote() {
  const [long, setLong] = useState(false);
  return <>
    <button onClick={() => setLong(v => !v)}>Change note length</button>
    <Note text={long ? 'A longer note that wraps over several lines above the reference point.' : 'A short note.'} />
  </>;
}

Read the code

The first render provides a measurable DOM node. Measuring height requests a corrected render before paint. This is a positioning lesson, not a complete tooltip widget.

Try a change

Use ResizeObserver to recompute the note height when it resizes. Keep observer cleanup, and avoid turning all Effects into layout Effects.

Common mistake

Server rendering has no browser layout to measure. Font loading, resizing and scroll can invalidate one measurement; production floating UI needs to handle those conditions too.

Official reading: useLayoutEffect

12HooksAdvanced

useInsertionEffect / style-library integration

A specialist Hook for inserting CSS before layout Effects read the page.

Application code normally imports CSS. Runtime styling libraries may need to insert a rule before layout Effects measure elements. This Hook is not a general-purpose faster Effect: refs are not attached yet, DOM mutation order is not a safe assumption, and state updates are not allowed.

Signature
useInsertionEffect(setup, dependencies);
RuntimeStyle.jsx
import { useInsertionEffect } from 'react';
// Educational only: fixed trusted CSS, not user-supplied text.
function useWarningStyle() {
  useInsertionEffect(() => {
    const style = document.createElement('style');
    style.textContent = '.runtime-warning { border: 2px solid currentColor; padding: 12px; }';
    document.head.appendChild(style);
    return () => style.remove();
  }, []);
}
export default function RuntimeStyle() {
  useWarningStyle();
  return <p className="runtime-warning">Unsaved changes</p>;
}

Read the code

The rule is inserted in the client and removed when the owner is cleaned up. It is deliberately tiny so you can see the insertion boundary.

Try a change

Replace the Hook with a normal CSS import. Explain why that is the better choice for a normal application.

Common mistake

This example is not a production CSS-in-JS engine. Real engines need rule deduplication, reference counting, SSR extraction and CSP support. Never interpolate untrusted input into CSS.

13HooksAdvancedReact 19.2+

useEffectEvent / fresh values inside an Effect

Separate reactive connection setup from non-reactive event behavior.

An Effect Event reads the latest committed props and state when an Effect calls it. Use it when the event should see fresh values without reconnecting the external system. It is not a replacement for a normal click handler or a trick for hiding dependencies.

Signature
const onTick = useEffectEvent(() => { /* reads fresh values */ });
FreshNotification.jsx
import { useEffect, useEffectEvent, useState } from 'react';
function Reminder({ intervalMs, name }) {
  const [last, setLast] = useState('Waiting for a reminder');
  const notify = useEffectEvent(() => {
    setLast('Reminder for ' + name + ' at ' + new Date().toLocaleTimeString());
  });
  useEffect(() => {
    const id = setInterval(() => notify(), intervalMs);
    return () => clearInterval(id);
  }, [intervalMs]);
  return <p role="status">{last}</p>;
}
export default function FreshNotification() {
  const [name, setName] = useState('Asha');
  return <>
    <input aria-label="Name" value={name} onChange={e => setName(e.target.value)} />
    <Reminder name={name} intervalMs={3000} />
  </>;
}

Read the code

Changing name affects the next reminder, but does not restart its interval. intervalMs remains a real setup dependency.

Try a change

Add an enabled prop that really controls subscription setup. Keep enabled in dependencies while leaving name inside the Effect Event.

Common mistake

Call the Effect Event only from Effect logic in the same component or Hook. Do not pass it to children or include it in dependencies. Its function identity is not stable.

Official reading: useEffectEvent

14HooksAdvancedReact 19 ref prop

useImperativeHandle / a small ref interface

Expose a narrow command interface instead of an entire DOM node.

Prefer declarative props for normal data flow. A parent may still need to focus, select or scroll a child. This Hook lets the child decide which commands are exposed through its ref. React 19 function components can receive ref as a prop.

Signature
useImperativeHandle(ref, () => handle, dependencies);
ImperativeSearch.jsx
import { useImperativeHandle, useRef, useState } from 'react';
function SearchField({ ref, value, onChange }) {
  const input = useRef(null);
  useImperativeHandle(ref, () => ({
    focus() { input.current?.focus(); },
    selectAll() { input.current?.select(); }
  }), []);
  return <input ref={input} aria-label="Search tickets" value={value}
    onChange={e => onChange(e.target.value)} />;
}
export default function ImperativeSearch() {
  const field = useRef(null);
  const [query, setQuery] = useState('invoice');
  return <>
    <SearchField ref={field} value={query} onChange={setQuery} />
    <button onClick={() => field.current?.selectAll()}>Select query</button>
  </>;
}

Read the code

The parent receives only focus and selectAll. value stays controlled by props, so the command interface does not secretly own application data.

Try a change

Add scrollIntoView as a command. Compare the API with passing a raw DOM ref.

Common mistake

Do not expose methods such as setPrice that bypass your state ownership. Include reactive values in handle dependencies when methods close over them.

Official reading: useImperativeHandle

15HooksAdvanced

useMemo / cache a calculation

Use it for measured expensive work or identity needed by an optimization.

useMemo keeps a calculation result while its dependencies compare equal with Object.is. It is a performance tool, not permanent storage, a request cache or a correctness guarantee. The calculation must stay pure.

Signature
const result = useMemo(() => calculate(input), [input]);
InvoiceSummary.jsx
import { useMemo, useState } from 'react';
const invoices = Array.from({ length: 4000 }, (_, i) => ({
  id: i + 1, amount: 100 + i, paid: i % 3 === 0
}));
export default function InvoiceSummary() {
  const [paidOnly, setPaidOnly] = useState(false);
  const [note, setNote] = useState('');
  const summary = useMemo(() => {
    const visible = invoices.filter(x => !paidOnly || x.paid);
    return { count: visible.length,
      total: visible.reduce((sum, x) => sum + x.amount, 0) };
  }, [paidOnly]);
  return <>
    <label><input type="checkbox" checked={paidOnly}
      onChange={e => setPaidOnly(e.target.checked)} />Paid only</label>
    <input aria-label="Private note" value={note} onChange={e => setNote(e.target.value)} />
    <p>{summary.count} invoices / {summary.total} total</p>
  </>;
}

Read the code

Typing a note leaves paidOnly unchanged, so the calculation may reuse its result. invoices is a stable module-level constant in this lesson.

Try a change

Measure with and without memoization. Then move invoices into a prop and include it in dependencies.

Common mistake

Creating an options object outside the calculation and listing it as a dependency can invalidate the cache every render. Memoizing tiny expressions often adds complexity without value.

useCallback / cache function identity

Useful when a stable callback lets another optimization work.

useCallback returns a function with stable identity while its dependencies are unchanged. It does not call the function, make its work faster, or stop the parent from rendering. The usual partner is a memoized child.

Signature
const handler = useCallback((input) => { /* event logic */ }, [deps]);
StableRow.jsx
import { memo, useCallback, useState } from 'react';
const items = [{ id: 'a', title: 'Login' }, { id: 'b', title: 'Billing' }];
const TicketRow = memo(function TicketRow({ ticket, onSelect }) {
  return <button onClick={() => onSelect(ticket.id)}>{ticket.title}</button>;
});
export default function StableRow() {
  const [selected, setSelected] = useState(null);
  const [note, setNote] = useState('');
  const onSelect = useCallback(id => setSelected(id), []);
  return <>

import { startTransition, useOptimistic, useRef, useState, useTransition } from 'react';

  const [notes, setNotes] = useState([]);

Call backend APIs without race conditions

Handle loading, errors, empty responses, cancellation and stale results.

The browser fetch API is not React-specific. React manages how request results affect the screen. Check response.ok because HTTP failures do not automatically reject fetch. Validate response data before trusting its shape. An aborted client request also does not guarantee that a server-side write was undone.

useTickets.js
import { useEffect, useState } from 'react';
export function useTickets(query, retryKey = 0) {
  const key = query.trim();
  const [result, setResult] = useState({ key: null, status: 'loading', data: [], error: '' });
  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setResult({ key, status: 'loading', data: [], error: '' });
    async function load() {
      try {
        const response = await fetch('/api/tickets?query=' + encodeURIComponent(key),
          { signal: controller.signal });
        if (!response.ok) throw new Error('Request failed: HTTP ' + response.status);
        const body = await response.json();
        if (!Array.isArray(body.items) || body.items.some(x =>
          typeof x.id !== 'string' || typeof x.title !== 'string')) {
          throw new Error('Unexpected ticket response');
        }
        if (active) setResult({ key, status: 'success', data: body.items, error: '' });
      } catch (err) {
        if (active && !controller.signal.aborted) {
          setResult({ key, status: 'error', data: [],
            error: err instanceof Error ? err.message : 'Request failed' });
        }
      }
    }
    load();
    return () => { active = false; controller.abort(); };
  }, [key, retryKey]);
  // Never display old-query data under a new query before its Effect runs.
  return result.key === key ? result
    : { key, status: 'loading', data: [], error: '' };
}

function send(res, status, data) {
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8',
    'Cache-Control': 'no-store', 'X-Content-Type-Options': 'nosniff' });

async function readJson(req) {
  let size = 0;
  const parts = [];
  for await (const part of req) {
    size += part.length;
    if (size > 16384) throw Object.assign(new Error('Body too large'), { status: 413 });
    parts.push(part);
  }
  try { return JSON.parse(Buffer.concat(parts).toString('utf8')); }
  catch { throw Object.assign(new Error('Invalid JSON'), { status: 400 }); }
}
const server = http.createServer(async (req, res) => {
  try {
    const url = new URL(req.url, 'http://localhost');
    if (req.method === 'GET' && url.pathname === '/api/tickets') {
      const query = (url.searchParams.get('query') ?? '').toLowerCase();
      const status = url.searchParams.get('status') ?? 'all';
      const delay = Number(url.searchParams.get('delay') ?? 200);
      await new Promise(r => setTimeout(r, Number.isFinite(delay) ? Math.max(0, Math.min(delay, 1500)) : 200));
      const items = [...tickets.values()].filter(t => t.title.toLowerCase().includes(query)
        && (status === 'all' || t.status === status));
      return send(res, 200, { items });
    }
    if (req.method === 'POST' && url.pathname === '/api/tickets') {
      const body = await readJson(req);
      const title = typeof body?.title === 'string' ? body.title.trim() : '';
      const token = body?.clientMutationId;
      if (title.length < 2 || title.length > 120 || typeof token !== 'string' || token.length < 8 || token.length > 100) {
        return send(res, 422, { error: 'Use a 2-120 character title and a valid mutation ID.' });
      }
      if (creations.has(token)) {
        const old = creations.get(token);
        if (old.title !== title) return send(res, 409, { error: 'Mutation ID was used with different data.' });
        return send(res, 200, { ticket: tickets.get(old.id) });
      }
      if (title.toLowerCase() === 'fail') return send(res, 422, { error: 'Demo rejection. Change the title and retry.' });
      // This local in-memory create is synchronous after validation, including the dedupe record.
      const ticket = { id: randomUUID(), title, status: 'open', version: 1 };
      tickets.set(ticket.id, ticket);
      creations.set(token, { title, id: ticket.id });
      return send(res, 201, { ticket });
    }
    if (req.method === 'PATCH' && url.pathname.startsWith('/api/tickets/')) {
      const id = decodeURIComponent(url.pathname.slice('/api/tickets/'.length));
      const old = tickets.get(id);
      if (!old) return send(res, 404, { error: 'Ticket not found' });
      const body = await readJson(req);
      if (!body || !['open', 'closed'].includes(body.status) || !Number.isInteger(body.version)) {
        return send(res, 422, { error: 'A valid status and integer version are required.' });
      }
      // Re-read after await so concurrent writes cannot use a stale pre-body-read snapshot.
      const latest = tickets.get(id);
      if (latest.version !== body.version) return send(res, 409, { error: 'Ticket changed. Refresh and retry.' });
      const ticket = { ...latest, status: body.status, version: latest.version + 1 };
      tickets.set(id, ticket);
      return send(res, 200, { ticket });
    }
    send(res, 404, { error: 'Not found' });
  } catch (err) {
    if (!res.headersSent) send(res, err.status ?? 500,
      { error: err.status ? err.message : 'Unexpected server error' });
    else res.end();
  }

export async function request(path, { signal, method = 'GET', body } = {}) {
  const response = await fetch(path, {
    method, signal,
    headers: body === undefined ? undefined : { 'Content-Type': 'application/json' },
    body: body === undefined ? undefined : JSON.stringify(body)
  });

}

export function useBoardTickets(query, status, refreshKey) {
  const key = JSON.stringify([query, status, refreshKey]);
  const [result, setResult] = useState({ key: null, status: 'loading', items: [], error: '' });
  useEffect(() => {
    const abort = new AbortController();
    let active = true;
    setResult({ key, status: 'loading', items: [], error: '' });
    const params = new URLSearchParams({ query, status });
    request('/api/tickets?' + params, { signal: abort.signal }).then(data => {
      if (!Array.isArray(data.items) || !data.items.every(validTicket)) throw new Error('Invalid ticket data');
      if (active) setResult({ key, status: 'success', items: data.items, error: '' });
    }).catch(err => {
      if (active && !abort.signal.aborted) setResult({ key, status: 'error', items: [], error: err.message });
    });
    return () => { active = false; abort.abort(); };
  }, [key, query, status]);
  return result.key === key ? result : { key, status: 'loading', items: [], error: '' };
}

Answer: B. Error Boundaries are not a universal catch for every asynchronous callback. Handle the operation at the boundary where it runs.

41. A portal changes which relationship?
  1. DOM placement, not the React ownership/context tree
  2. The parent context automatically
  3. The module import graph
  4. Every event into a native-only event

Answer: A. Portal content is physically placed elsewhere in the DOM but still belongs to its React parent tree.

42. A memoized child receives a new inline object on each render. What happens?
  1. The object is deeply compared for free
  2. The new prop identity can defeat memoization
  3. React forbids object props
  4. The child never renders

Answer: B. Default memo comparison checks prop equality with Object.is, not a deep structural comparison.

43. What should you do before spreading memoization throughout a slow page?
  1. Guess which Hook is fastest
  2. Measure the slow interaction and inspect the work
  3. Disable Strict Mode permanently
  4. Move every state value to context

Answer: B. Performance fixes should target measured work: unnecessary renders, expensive calculations, network waterfalls or excessive DOM size.

44. What happens to Effects inside a hidden Activity?
  1. They keep running exactly as with CSS-only hiding
  2. They are cleaned up and recreated when shown
  3. They become Server Functions
  4. They permanently lose state

Answer: B. Activity preserves state/DOM but changes Effect lifetime. CSS-only hiding does not do the same cleanup.

45. Why can hidden media require extra cleanup?
  1. Activity deletes all DOM immediately
  2. A preserved video/audio DOM element may continue playing
  3. Refs stop existing in React 19
  4. Browsers do not support pause

Answer: B. Preserving a DOM node can preserve its media behavior. Explicitly pause media in appropriate cleanup.

46. In which release did the checked official docs mark ViewTransition stable?
  1. React 17
  2. React 18.0
  3. React 19.3
  4. It is still described as experimental in this guide

Answer: C. The React 19.3 release, dated 9 September 2026, makes View Transitions stable for React DOM.

47. How should an animation handle reduced-motion preference?
  1. Ignore it because the animation is small
  2. Provide reduced or disabled animation
  3. Require the user to stop using the app
  4. Disable all keyboard interaction

Answer: B. Keep the interface usable while reducing optional motion for users who request it.

48. What does a ref on explicit Fragment expose in React 19.3?
  1. An extra wrapper div
  2. A FragmentInstance with documented group operations
  3. A database cursor
  4. An ordinary string key

Answer: B. Fragment refs operate on the existing child group without adding a wrapper. Do not assume arbitrary HTMLElement properties.

49. What does use(browser()) do during SSR?
  1. It silently renders localStorage from the server
  2. It suspends that component so a surrounding fallback can render
  3. It installs a browser on the server
  4. It changes every parent into a Client Component

Answer: B. browser() provides a targeted browser-only rendering boundary using Suspense. It does not rewrite the module graph.

50. Does installing React 19.3 automatically enable React Compiler?
  1. Yes
  2. No; the compiler requires build-tool integration
  3. Only for components called App
  4. Only if useMemo appears

Answer: B. Compiler is a separate build-time optimization. The React runtime version alone does not turn it on.

51. In React 19-only function components, how may a child receive a ref?
  1. As a ref prop
  2. Only through a class
  3. Only through a Redux store
  4. It cannot receive a ref

Answer: A. React 19 allows the ref prop directly. forwardRef remains useful for older-version compatibility.

52. Does Trusted Types support mean React sanitizes all HTML?
  1. Yes, all HTML is automatically safe
  2. No; the application still needs a reviewed sanitization policy
  3. Only if the string is short
  4. Only for server data

Answer: B. Passing trusted typed values to sinks preserves browser policy enforcement. It is not automatic sanitization of arbitrary strings.

53. Which API attaches React to matching server-rendered HTML?
  1. createRoot for every case
  2. hydrateRoot
  3. createPortal
  4. renderToStaticMarkup in the browser

Answer: B. hydrateRoot is for existing server HTML. createRoot is the starting point for a client-rendered root.

54. Is every component that appears in SSR HTML a Server Component?
  1. Yes
  2. No; SSR can also pre-render Client Components
  3. Only if it uses a button
  4. Only if it imports CSS

Answer: B. SSR describes producing HTML. Server Components describe a different execution/module boundary managed by an RSC framework.

55. What must a Server Function do with a client-supplied ticket ID?
  1. Trust it because the caller used React
  2. Authenticate, validate and authorize the operation
  3. Only check that the button was visible
  4. Skip checks when TypeScript compiles

Answer: B. Server Functions are server entry points. Client UI and type checking do not enforce access control.

56. Is React cache a persistent database or cross-request Redis replacement?
  1. Yes
  2. No; it is tied to Server Component render caching
  3. Only for strings
  4. Only when called twice

Answer: B. Use the documented cache lifetime. Durable or cross-request caching requires an intentional separate design.

57. A server renders one timestamp and the client initially renders a different timestamp. What should you do?
  1. Ignore every hydration warning
  2. Make the initial output consistent or intentionally isolate browser-only content
  3. Call createRoot after hydrateRoot
  4. Add random keys

Answer: B. Hydration expects matching initial output. Fix the source of non-determinism rather than concealing all warnings.

58. Which test query most closely reflects how a user finds a button?
  1. getByRole('button', { name: 'Save' })
  2. querySelector('div:nth-child(4)')
  3. Find a private Hook state variable
  4. Read the minified component name

Answer: A. Accessible roles and names produce tests that follow user-facing semantics rather than fragile implementation details.

59. A total can be calculated from items. What is usually simplest?
  1. Separate total state updated by an Effect
  2. Calculate it during render; memoize only if justified
  3. Store it in a ref and hope the page updates
  4. Ask the DOM to sum text nodes

Answer: B. Derived values usually do not need independent state. Extra synchronization introduces unnecessary renders and opportunities for inconsistency.

60. Does casting parsed JSON as Ticket[] validate the response at runtime?
  1. Yes
  2. No; validate runtime input separately
  3. Only in production
  4. Only with strict mode

Answer: B. Type assertions do not inspect network data. Runtime validation and static types solve different problems.
