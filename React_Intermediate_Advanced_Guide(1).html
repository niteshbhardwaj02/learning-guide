Rendering, snapshots, and identity

A component describes a screen for one moment in time.

A render is React calling your component to calculate JSX. A commit applies the necessary DOM changes. A render may be restarted or abandoned, so rendering must not send requests, mutate shared data, or start subscriptions.

State belongs to a component's position in the tree. Type and key influence that identity. Changing the key below deliberately creates a fresh editor. Keeping it preserves the draft even when the parent renders again.

Each render has its own values and event-handler closures. Calling a setter schedules another render; it does not rewrite variables in the handler that is already running. This explains many stale-value bugs. Do not define component functions inside another component: a new function identity can unexpectedly reset state.

Read the code. Predict the behavior.

Standalone App.jsx - reset a draft intentionally
jsx
import { useState } from 'react';

function Draft({ customer }) {
  const [text, setText] = useState('');
  return <label>Note for {customer}
    <textarea value={text} onChange={e => setText(e.target.value)} />
  </label>;
}
export default function App() {
  const [customer, setCustomer] = useState('Asha');
  return <>
    <select value={customer} onChange={e => setCustomer(e.target.value)}>
      <option>Asha</option><option>Kabir</option>
    </select>
    <Draft key={customer} customer={customer} />
  </>;
}

Watch for these mistakes

  • A re-render is not the same as a DOM replacement.
  • Array indexes are unsafe keys when items can be inserted, removed, or reordered. Use persistent data IDs.

Composition and component contracts

Prefer a few clear inputs over dozens of boolean switches.

A reusable component should expose its purpose, not every internal implementation detail. A card can accept a heading, content, and actions. The caller owns the business decision; the card owns the layout.

Composition means combining components through props and children. Named JSX props act as slots. A render prop is a function supplied by the caller when rendering needs data from the child. Prefer ordinary children when no function is necessary.

Avoid a giant component such as <Card isAdmin isCompact isProduct isEditable />. Separate responsibilities instead. Keep rapidly changing state near the part of the screen that uses it. A wrapper receiving already-created children can often update its own state without causing those children to render again.

Read the code. Predict the behavior.

Standalone App.jsx - slots and controlled behavior
jsx
import { useState } from 'react';

function Panel({ title, actions, children }) {
  return <section aria-label={title}>
    <header><h2>{title}</h2>{actions}</header>
    <div>{children}</div>
  </section>;
}
function SearchInput({ value, onValueChange }) {
  return <label>Search tasks
    <input value={value} onChange={e => onValueChange(e.target.value)} />
  </label>;
}
export default function App() {
  const [query, setQuery] = useState('');
  return <Panel title="Task search"
    actions={<button onClick={() => setQuery('')}>Clear</button>}>
    <SearchInput value={query} onValueChange={setQuery} />
    <p>Searching for: {query || '(everything)'}</p>
  </Panel>;
}

Watch for these mistakes

  • Do not copy a controlled prop into state unless you intentionally want an independent initial draft.
  • Spreading arbitrary props can leak invalid attributes to DOM elements. Design the public contract.

LESSON 04 / 47 Component foundations
AdvancedStable

Compound components and shared state

Let related pieces cooperate without exposing their wiring.

A compound component is an API made from cooperating pieces. Here, an accordion item owns its open state; its trigger and panel read that state through context. Callers control the layout while the implementation keeps behavior consistent.

The custom Hook throws a useful error when a piece is placed outside its provider. Each accordion item owns a separate provider, so opening one does not open all of them. Native buttons already support keyboard activation.

This is useful for accordions, menus, and form groups. It is not permission to hide every prop in context. Use direct props for simple relationships. More complex widgets such as tabs need a complete keyboard and focus design beyond this accordion example.

Read the code. Predict the behavior.

Standalone App.jsx - accessible accordion composition
jsx
import { createContext, useContext, useId, useState } from 'react';
const ItemContext = createContext(null);
function useItem() {
  const value = useContext(ItemContext);
  if (!value) throw new Error('Use these parts inside AccordionItem');
  return value;
}
function AccordionItem({ children }) {
  const [open, setOpen] = useState(false);
  const id = useId();
  return <ItemContext value={{ open, setOpen, id }}>{children}</ItemContext>;
}
function Trigger({ children }) {
  const { open, setOpen, id } = useItem();
  return <h3><button id={id + '-trigger'} aria-expanded={open}
    aria-controls={id + '-panel'} onClick={() => setOpen(v => !v)}>
    {children}
  </button></h3>;
}
function Panel({ children }) {
  const { open, id } = useItem();
  return <div id={id + '-panel'} aria-labelledby={id + '-trigger'} hidden={!open}>
    {children}
  </div>;
}
export default function App() {
  return <AccordionItem><Trigger>What is a Hook?</Trigger>
    <Panel>A function that connects your component to a React feature.</Panel>
  </AccordionItem>;
}

Watch for these mistakes

  • Every useContext call subscribes to the entire provided value, not one property.
  • Do not use cloneElement to secretly inject a large web of behavioral props when explicit composition is clearer.

useState

Store the smallest amount of information your UI needs.

useState(initial) returns a value and a setter. Use it for input text, selected IDs, and simple flags. Derive values such as totals during render instead of storing a second state variable that can become inconsistent.

When the next value depends on the previous one, an updater function expresses that dependency. Three calls using the same snapshot are different from three queued updaters. React batches updates, but batching does not mutate your local variable.

Replace objects and arrays rather than mutating them. A lazy initializer, useState(() => expensiveInitialValue()), avoids recalculating initial data on later renders. Keep the initializer and updaters pure.

Standalone App.jsx - snapshot versus updater queue
jsx
import { useState } from 'react';
export default function App() {
  const [quantity, setQuantity] = useState(0);
  const total = quantity * 250; // Derived, not another state variable.
  function addFromSnapshot() {
    setQuantity(quantity + 1);
    setQuantity(quantity + 1);
    setQuantity(quantity + 1); // Three replacements with the same value.
  }
  function addFromQueue() {
    setQuantity(q => q + 1);
    setQuantity(q => q + 1);
    setQuantity(q => q + 1);
  }
  return <>
    <p>{quantity} items; total INR {total}</p>
    <button onClick={addFromSnapshot}>Snapshot x3: adds 1</button>
    <button onClick={addFromQueue}>Updater x3: adds 3</button>
    <button onClick={() => setQuantity(0)}>Reset</button>
  </>;
}

Watch for these mistakes

  • setState does not return a Promise; awaiting it does not wait for a commit.
  • Mutating the same object can defeat Object.is equality checks and corrupt previous snapshots.

LESSON 06 / 47 Every Hook
IntermediateStable

useReducer

Turn complicated state changes into named events.

useReducer(reducer, initialState) returns state and dispatch. The reducer receives the old state and an action, then returns the next state. It should not fetch data, modify the DOM, or generate random IDs.

Use it when several fields must change together or when many event handlers repeat the same rules. A cart reducer makes transitions such as added, removed, and cleared easy to test without mounting React.

A reducer does not automatically make state global or faster. Its value is organized logic. Send semantic actions, not a generic patch for every possible object shape.

Read the code. Predict the behavior.

Standalone App.jsx - reducer with an invariant
jsx
import { useReducer } from 'react';
export function cartReducer(state, action) {
  switch (action.type) {
    case 'added': return { ...state, quantity: state.quantity + 1 };
    case 'removed': return { ...state, quantity: Math.max(0, state.quantity - 1) };
    case 'cleared': return { quantity: 0 };
    default: throw new Error('Unknown cart action: ' + action.type);
  }
}
export default function App() {
  const [cart, dispatch] = useReducer(cartReducer, { quantity: 0 });
  return <>
    <p>Quantity: {cart.quantity}</p>
    <button onClick={() => dispatch({ type: 'added' })}>Add</button>
    <button onClick={() => dispatch({ type: 'removed' })}>Remove</button>
    <button onClick={() => dispatch({ type: 'cleared' })}>Clear</button>
  </>;
}

Watch for these mistakes

  • Reducers and initializers must stay pure, including under development Strict Mode checks.
  • For complex initialization, use the third argument: useReducer(reducer, initialArg, init).
YOUR TURN

Reveal the reasoning

LESSON 07 / 47 Every Hook
IntermediateStable

useContext + createContext

Share a value through a tree, without passing it through every layer.

Create the context outside component functions. A consumer reads the nearest matching provider above it and subscribes to changes. The default value is a fallback when there is no provider, not a value React merges with a provider.

Context fits themes, session information, locale, and scoped services. Keep rapidly changing state local when possible. Split unrelated contexts so a mouse-position update does not refresh every theme consumer.

React 19 allows <ThemeContext value={theme}>. Older code uses <ThemeContext.Provider>. memo does not block updates caused by a context that the memoized component reads.

Read the code. Predict the behavior.

Standalone App.jsx - scoped preference
jsx
import { createContext, useContext, useState } from 'react';
const ThemeContext = createContext('light');
function Preview() {
  const theme = useContext(ThemeContext);
  return <p>Preview theme: {theme}</p>;
}
export default function App() {
  const [theme, setTheme] = useState('light');
  return <ThemeContext value={theme}>
    <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>
      Change theme
    </button>
    <Preview />
  </ThemeContext>;
}

Watch for these mistakes

  • An object literal used as the provider value is a new object on every parent render. Memoize when measured and useful, or split state and actions.
  • Context is not a replacement for server authorization or a query cache.

useRef

Keep a mutable value that does not itself drive the screen.

A ref object survives re-renders. Changing ref.current does not schedule a render. Use it for DOM nodes, timer handles, and information needed by event handlers but not directly displayed.

If the user should see a value change, use state. A ref is not a shortcut around the rendering model. Read or write it in events and effects, not as an uncontrolled side effect of rendering.

This search box focuses its input without making focus a state variable. React assigns the DOM node during commit. It is initially null, so code must allow for a missing node.

Read the code. Predict the behavior.

Standalone App.jsx - focus without a re-render
jsx
import { useRef, useState } from 'react';
export default function App() {
  const inputRef = useRef(null);
  const [query, setQuery] = useState('');
  return <>
    <label>Search
      <input ref={inputRef} value={query}
        onChange={e => setQuery(e.target.value)} />
    </label>
    <button onClick={() => inputRef.current?.focus()}>Focus search</button>
    <p>Query: {query}</p>
  </>;
}

Watch for these mistakes

  • Using ref.current as an Effect dependency does not make it reactive.
  • Do not use a ref to hide missing Effect dependencies.

useImperativeHandle

Expose a tiny command API instead of your entire DOM structure.

This Hook controls what a parent receives through a ref. A component can expose focus() and clear() while keeping its internal input private. It is useful for imperative actions such as selecting text or controlling media.

In React 19, a function component can receive ref as a prop. forwardRef remains relevant when maintaining React 18-compatible libraries. Prefer props for stateful behavior such as whether a dialog is open.

The dependency array follows normal reactive-value rules. The handle below needs no changing render values: it calls a stable state setter and reads a stable ref object when the method is invoked.

Read the code. Predict the behavior.

Standalone App.jsx - React 19 ref prop
jsx
import { useImperativeHandle, useRef, useState } from 'react';
function SearchBox({ ref }) {
  const input = useRef(null);
  const [value, setValue] = useState('');
  useImperativeHandle(ref, () => ({
    focus() { input.current?.focus(); },
    clear() { setValue(''); }
  }), []);
  return <label>Search
    <input ref={input} value={value} onChange={e => setValue(e.target.value)} />
  </label>;
}
export default function App() {
  const search = useRef(null);
  return <>
    <SearchBox ref={search} />
    <button onClick={() => search.current?.focus()}>Focus</button>
    <button onClick={() => search.current?.clear()}>Clear</button>
  </>;
}

Watch for these mistakes

  • Do not expose every internal method; that creates tight coupling.
  • A captured reactive value must be included in the dependency array or read through a correctly designed event-time mechanism.

LESSON 10 / 47 Every Hook
IntermediateStable

useEffect

Synchronize with something outside React.

An Effect keeps an external system aligned with the currently committed UI. Examples include an event subscription, a network connection, or a browser timer. It is not a general place to calculate derived values.

For changed dependencies, React cleans up the old synchronization and starts the new one. Cleanup also runs on unmount. Dependencies are compared with Object.is. Include every reactive value used by the setup, rather than silencing the linter.

Effects run on the client, not during server rendering. Non-interaction Effects generally run after paint, but there are timing exceptions. Use useLayoutEffect for work that must block a visual paint. Development Strict Mode can add a setup-cleanup cycle to expose incomplete cleanup.

Standalone App.jsx - subscription with symmetrical cleanup
jsx
import { useEffect, useState } from 'react';
export default function App() {
  const [enabled, setEnabled] = useState(true);
  const [lastKey, setLastKey] = useState('none');
  useEffect(() => {
    if (!enabled) return;
    function onKeyDown(event) { setLastKey(event.key); }
    window.addEventListener('keydown', onKeyDown);
    return () => window.removeEventListener('keydown', onKeyDown);
  }, [enabled]);
  return <>
    <label><input type="checkbox" checked={enabled}
      onChange={e => setEnabled(e.target.checked)} /> Listen to keys</label>
    <p>Last key: {lastKey}</p>
  </>;
}

Watch for these mistakes

  • Do not make the Effect callback async: React expects cleanup or undefined, not a Promise. Define and call an async function inside it.
  • A POST caused by a user clicking Buy belongs in the event or action, not an Effect watching a bought flag.

LESSON 11 / 47 Every Hook

useLayoutEffect

Measure committed layout before the browser paints.

Sometimes rendering requires a second pass after reading DOM geometry. A tooltip may need its measured size before choosing a position. useLayoutEffect runs before the browser repaints, and state updates inside it can block that paint.

This example centers a label over a track after measuring its width. The hidden initial pass avoids flashing a wrongly positioned label. A CSS solution is preferable when it can express the same layout.

There is no browser layout on a server. Use a client boundary or a suitable fallback for server-rendered measurement-dependent UI. Overusing this Hook delays visible updates.

Read the code. Predict the behavior.

Standalone App.jsx - measured label
jsx
import { useLayoutEffect, useRef, useState } from 'react';
function Marker({ text }) {
  const ref = useRef(null);
  const [width, setWidth] = useState(null);
  useLayoutEffect(() => {
    const node = ref.current;
    if (!node) return;
    const measure = () => setWidth(node.getBoundingClientRect().width);
    measure();
    const observer = new ResizeObserver(measure);
    observer.observe(node);
    return () => observer.disconnect();
  }, [text]);
  return <div style={{ position: 'relative', width: 300, height: 50 }}>
    <span ref={ref} style={{ position: 'absolute',
      left: 150 - (width ?? 0) / 2, visibility: width === null ? 'hidden' : 'visible' }}>
      {text}
    </span>
  </div>;
}
export default function App() { return <Marker text="Centered measurement" />; }

Watch for these mistakes

  • Expensive calculations here block paint.
  • Do not use it merely because it sounds more powerful than useEffect.

useInsertionEffect

A specialized tool for runtime CSS library authors.

This Hook lets a style-injection library insert rules before layout Effects read layout. Application code should normally use stylesheets, CSS modules, or inline styles instead.

Do not rely on whether the DOM has already changed when it runs. Refs are not yet attached, and setting state inside this Hook is not allowed. It does not run on the server.

The example is deliberately a small client-only library exercise, not a production CSS engine. A production implementation must address deduplication, ordering, server extraction, CSP, and hydration.

Read the code. Predict the behavior.

Standalone App.jsx - library mechanism demonstration
jsx
import { useInsertionEffect } from 'react';
function useDemoStyle(rule) {
  useInsertionEffect(() => {
    const style = document.createElement('style');
    style.textContent = rule; // Only trusted, developer-authored CSS here.
    document.head.appendChild(style);
    return () => style.remove();
  }, [rule]);
}
export default function App() {
  useDemoStyle('.demo-outline { outline: 3px solid currentColor; padding: 12px; }');
  return <p className="demo-outline">Runtime CSS insertion demo</p>;
}

Watch for these mistakes

  • Do not measure nodes or update state here.
  • A plain CSS file is the better solution for this demo in a real application.

cache + cacheSignal

Deduplicate server-render work without inventing a global user cache.

React's cache is intended for Server Components. It memoizes a function for the relevant server render/request lifetime, including thrown errors. Create the cached wrapper once and import it where needed. Calling cache separately creates separate memoized functions.

Use primitive IDs when appropriate because argument identity matters. This is not the browser query cache and not a durable cross-request cache. A Map at module scope is not an equivalent safe replacement for per-request, user-aware behavior.

cacheSignal exposes an abort signal associated with React's cache lifetime in supported server rendering contexts. It lets compatible operations stop when the cached work is no longer needed. Outside the relevant scope, do not assume it provides an active signal.

Legacy APIs and migration decisions

Recognize older patterns without using them as your default.

Existing code may use classes, PureComponent, createRef, forwardRef, Children utilities, cloneElement, or createElement. Understanding them helps with maintenance. Prefer functions, composition, and Hooks for new application code unless a specific constraint requires otherwise.

createElement creates a React element without JSX. isValidElement checks for an element, not every renderable React node. Children helpers operate on the children structure they receive, not the fully rendered output of nested components. Cloning elements can make data flow harder to follow.

React 19 removed old React DOM entry points such as render, hydrate, findDOMNode, and unmountComponentAtNode. Migrate to createRoot, hydrateRoot, refs, and root.unmount. captureOwnerStack is a development diagnostic API, not a production contract; use supported root error callbacks and application monitoring for production reporting.
