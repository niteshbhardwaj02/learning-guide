Domain 01 / Questions 1–10

Language, scope and types

001How do var, let and const differ beyond syntax?
Output

var is function-scoped (or global-script-scoped) and its binding is initialized to undefined before ordinary execution. let and const are lexical bindings with a temporal dead zone until initialization. const prevents rebinding, not object mutation. Top-level declarations also differ between classic scripts, ES modules and Node.js wrappers. Prefer the narrowest scope and make the execution context explicit when explaining output.

Code check

What happens when this block executes?

{
  console.log(typeof x);
  let x = 1;
}

Answer: It throws ReferenceError before logging.

x is a lexical binding in its temporal dead zone. typeof only avoids ReferenceError for an unresolvable identifier, not an uninitialized lexical binding.

002What does a closure capture, and why does that matter?
Output

A closure retains access to its lexical environment, not a frozen snapshot of every value. Multiple closures may observe the same mutable binding; separate factory calls may create separate environments. This supports encapsulation, dependency injection and callbacks, but long-lived callbacks can retain unnecessary data. Diagnose the actual retained object graph rather than assuming every closure is a leak.

What is logged?

const read = () => n;
n = 2;
console.log(read());

Answer: 2

The function reads the current value of the captured n binding when called, after the assignment to 2.

003Why do callbacks in var loops often observe the final value?
Output

A var loop reuses one binding. Callbacks executed after the loop therefore read its final value. A for (let ...) loop creates per-iteration bindings, so callbacks can retain distinct iteration values. An explicit factory or immediately invoked function can also create separate scope. Changing a callback to an arrow function alone does not fix shared binding behavior.

Code check

console.log(...fns.map(fn => fn()));

Answer: 3 3 3

All three functions capture the same function-scoped i. Once the loop ends, that binding contains 3.

004How is this determined in regular and arrow functions?
Output

For ordinary functions, this depends on how the function is called: method call, explicit binding, constructor call or plain call. Arrows resolve this lexically and cannot be rebound with call, apply or bind. A detached method loses its receiver. In strict mode, a plain-call receiver is undefined. Choose an arrow for lexical capture and a method when receiver-based dispatch is intentional.

005Compare strict equality, Object.is and SameValueZero.
Output

=== avoids coercion, considers NaN unequal to itself, and treats positive and negative zero as equal. Object.is considers NaN equal to itself but distinguishes signed zero. SameValueZero, used for Map keys, Set membership and Array.includes, treats NaN as equal and merges signed zero. Object equality in these comparisons is identity-based, not structural. Pick a comparison that matches the domain rather than copying one everywhere.

Answer: true false 2

Object.is recognizes NaN as itself and distinguishes signed zero. Set uses SameValueZero, so duplicate NaN and signed zero values collapse.

006When should you use nullish coalescing instead of logical OR?
Output

|| uses its fallback for any falsy operand; ?? uses it only for null or undefined. Configuration values such as zero retries, an empty label or false flags may be meaningful and should not be silently replaced. Optional chaining stops on a nullish receiver, not on every invalid operation. It is not input validation, and grouping can end a continuous optional chain.

Code check

What is logged?

Answer: 5 0

Zero is falsy, so OR selects 5. Zero is not nullish, so nullish coalescing preserves it.

007Is JavaScript pass-by-reference?
Output

Arguments are passed by value. For an object, that value provides access to the same object identity, so mutating a property is visible to other holders. Reassigning the parameter does not reassign the caller's variable. This distinction explains many state-management bugs. Document whether an API mutates its input, and prefer immutable boundaries where shared mutation would make behavior difficult to reason about.

The property mutation changes the shared object to 2. Rebinding the local parameter to another object does not change a.

008How do you handle numeric precision and large identifiers?
Concept

Number uses binary floating-point and cannot exactly represent all integers beyond its safe-integer range or all decimal fractions. BigInt represents arbitrary-size integers but not fractional values. Most arithmetic cannot mix BigInt and Number without explicit conversion, and default JSON serialization of BigInt throws. For identifiers, preserve the original string; for exact decimal domains, choose an explicit decimal or scaled-integer representation with a rounding policy.

009What is the difference between a UTF-16 code unit, code point and grapheme?
Output

JavaScript string length and indexed access operate on UTF-16 code units. Iteration with for...of advances by Unicode code points, which still need not match user-perceived characters: combining marks and emoji sequences can span several code points. Use Intl.Segmenter with grapheme granularity for user-visible character operations where supported. Keep normalization and locale-sensitive comparison explicit at domain boundaries.

010How do shallow copying and freezing differ from deep immutability?
Output

Object spread copies enumerable own property values into a new object; nested object identities remain shared. Object.freeze restricts the frozen object's own properties but does not recursively freeze its graph. Accessor behavior and internal collection state require additional care. For application updates, copy the changed path or use a well-understood immutable-data strategy. Avoid treating freezing as a security sandbox.

The outer object is frozen, not its nested object. The spread copy shares that same nested object, so both observe 2.

Objects, collections and modules

011How does prototype lookup work, and what do classes add?
Output

An ordinary property read checks the object and then follows its prototype chain. Class methods normally live on the prototype; instance fields live on each instance. Classes add syntax and semantics such as strict-mode bodies, derived-constructor rules and private elements, not a separate inheritance model. Favor composition when inheritance would couple unrelated responsibilities, and avoid mutating built-in prototypes in shared environments.

Answer: true false

The in operator searches the prototype chain, while Object.hasOwn checks only the object itself.

012What do native private fields protect, and what are their limits?
Output

#private elements are enforced by the language and are not ordinary string-keyed properties. Access requires the appropriate private brand on the receiver. They differ from a naming convention and from TypeScript's compile-time-only private modifier. A proxy or detached method may fail a brand check even when it appears to wrap the original instance. Privacy is an encapsulation mechanism, not an authorization boundary.

013When should you choose Map over an object?
Output

Use objects for records with named fields and Map for dynamic keyed collections, especially with object keys. Map preserves insertion order and exposes collection operations directly; plain-object keys are strings or symbols and inherited properties can complicate dictionary logic. The specification requires average sublinear access for Map, not a universal strict O(1) guarantee. Consider serialization, key identity and lifecycle rather than assuming Map is always faster.

014When are WeakMap and WeakSet useful?
Concept

Weak collections associate metadata with garbage-collectable keys without keeping those keys alive solely through the collection. Keys can include objects and eligible non-registered symbols in current JavaScript; primitive strings are not valid WeakMap keys. They do not expose enumeration or size because that would reveal garbage-collection timing. Use them for identity-linked metadata, not for an LRU cache that needs predictable capacity and eviction.

015Why is JSON round-tripping not a general-purpose deep clone?
Concept

JSON represents a restricted data model: it drops or changes several JavaScript values, loses object identity and prototypes, and cannot directly encode cycles. structuredClone supports cyclic graphs and several built-in types, with transfer support for transferable resources. It is still not a universal clone: functions and many host objects cannot be cloned, and custom class behavior is not preserved as an equivalent instance. Define the required data contract first.

016What are ESM live bindings and how can circular imports fail?
Output

An ES-module import refers to an exported binding rather than taking a one-time value snapshot. Importers cannot assign to that binding, but they may observe changes made by the exporting module. Modules have linking and evaluation stages. A cycle is not automatically invalid; reading a lexical export before its initialization can fail. Break problematic initialization cycles with clearer dependency boundaries or deferred access.

017How do CommonJS and ESM differ in a production Node.js package?
Design

CommonJS exposes require and module.exports; ESM uses standardized import/export and live bindings. Their loading, resolution and interoperation rules are not interchangeable. Current Node versions have evolved ESM interop, so the old claim that require can never load ESM is too broad; top-level-await restrictions still matter. 018What are iterables, iterators and generators?
Output

An iterable supplies a method at Symbol.iterator; an iterator supplies next() results with value and done. A generator function creates an iterator that can suspend and resume, usually also iterable itself. These protocols enable lazy traversal and bounded-memory processing. Early loop exit can close an iterator through return(), so generator finally blocks can perform cleanup. Async iteration uses a related protocol for asynchronous values.

019What are Proxy and Reflect good for, and what can go wrong?
Concept

Proxy intercepts operations such as reads, writes and property checks; Reflect exposes corresponding default operations. Together they support validation, observation and membranes, but traps must respect language invariants. Receivers, accessors and built-in internal slots can make transparent forwarding difficult. Proxy also changes debugging and performance characteristics. Prefer explicit interfaces unless interception solves a genuine cross-cutting requirement.

Output

A comparator must be consistent rather than depending on changing external state. Consider locale-sensitive comparison and stable ordering where the business requirement calls for it.

Domain 03 / Questions 21–30

Async and concurrency

021Explain the browser event loop without oversimplifying rendering.
Output

Synchronous JavaScript runs to completion on its current agent. Tasks include events and timers; promise reactions and queueMicrotask callbacks use microtasks. At a microtask checkpoint, the queue drains, including newly queued microtasks. Rendering opportunities depend on the browser and are not guaranteed after every task. Recursively queuing microtasks can therefore delay input and rendering rather than making work responsive.

Code check

In a browser, what order is logged?

console.log("A");
setTimeout(() => console.log("T"), 0);
Promise.resolve().then(() => console.log("P"));
queueMicrotask(() => console.log("Q"));
console.log("B");

Answer: A B P Q T

Synchronous logs run first. The promise reaction and queueMicrotask callback run in enqueue order at the microtask checkpoint; the timer runs in a later task.

022What runs synchronously in a promise or async function?
Output

A Promise constructor invokes its executor synchronously. An async function executes synchronously until it suspends at await; its caller receives a promise. Even awaiting an already fulfilled promise resumes through asynchronous continuation rather than blocking the caller. Neither promises nor async functions automatically move CPU-heavy work off-thread. Use workers or restructure expensive work when parallel CPU execution is needed.

  console.log("A");
  await 0;
  console.log("B");
}

console.log("C");

Answer: A C B

The async function logs A before reaching await, then suspends. The caller logs C, and the continuation later logs B.

023How do Promise.all, allSettled, any and race differ?
Concept

all fulfills with input-order results only if every input fulfills and rejects on a rejection. allSettled waits for all outcomes. any fulfills on the first fulfillment and rejects with AggregateError if all reject. race follows the first settlement. These APIs observe promises; they do not inherently cancel other operations. Choose according to dependency semantics, and define cancellation and partial-result policies separately.

024Why does forEach(async ...) usually cause bugs?
Concept

forEach ignores callback return values, so it does not await the promises returned by async callbacks. The surrounding function can finish early and rejected callbacks may become unhandled. Use for...of with await for serial dependencies. Use map plus Promise.all for a small independent batch, or a concurrency-limited pool for a large one. State whether order, throughput or resource pressure is the primary requirement.

025What is bounded concurrency, and how is it different from batching?
Design

A concurrency limiter caps the number of active operations while starting another as a slot becomes free. Fixed batches wait for the slowest item before starting the next batch, which can underutilize capacity. A limiter should preserve required output order, propagate errors, stop scheduling when appropriate and cooperate with cancellation. Passing already-started promises cannot retroactively limit concurrency; supply work as callable operations.

026How should cancellation propagate through async APIs?
Concept

Accept an AbortSignal at the boundary and pass it to cooperating downstream work. Check an already-aborted signal, release resources and remove listeners when the operation settles. Cancellation is cooperative, not a universal thread interrupt; it may not undo server-side effects. Keep user cancellation distinct from faults in logging and UI behavior. Combine deadline and caller cancellation deliberately, with runtime support checks for convenience APIs.

Debugging

A try/catch catches synchronous throws and rejections from awaited work within it; it does not catch a later throw in an unrelated timer callback. Add useful context with an error cause, distinguish expected domain failures, and avoid swallowing errors or logging the same failure at every layer. 028How can race conditions occur on a single JavaScript thread?
Design

Run-to-completion prevents interleaving within one synchronous segment, not across awaits. Two operations can both read old state and later overwrite each other. Fix the invariant at the correct boundary: serialize local work, use version checks, apply database transactions or atomic operations, and make distributed writes idempotent. A process-local mutex does not coordinate other processes or services.

Debugging

Split long work into bounded chunks and yield via an appropriate task scheduler, or move suitable computation to a worker. Browser, UI and networking

031How does event delegation work, and what are its edge cases?
Concept

Attach a handler to a stable ancestor and identify matching descendants through the event path or closest matching element. It reduces per-element listeners and supports dynamic children. Distinguish target from currentTarget; handle capture, bubbling and shadow-DOM retargeting intentionally. Not every event bubbles. Scope closest matches to the intended container, and remember that preventDefault and stopPropagation solve different problems.

032What should a robust fetch wrapper handle?
Concept

Fetch normally fulfills for HTTP error responses such as 404 and 500; inspect status or ok before treating a response as success. Handle network failures, cancellation, content type, body parsing failures and expected empty responses separately. Request and response bodies are streams, usually consumed once. Bound response sizes where appropriate, attach deadlines, and retry only according to operation semantics rather than retrying every error.

Concept

CORS governs when browser code can access cross-origin responses, based on server-provided headers and sometimes a preflight. It is not authentication, authorization or a complete CSRF defense. Non-browser clients are not restricted by browser CORS enforcement. Credentialed cross-origin responses require appropriate explicit origin handling; a wildcard is not a universal solution. Concept

Node coordinates timers, pending callbacks, poll, check and close callbacks, alongside next-tick and microtask processing. Timer delays are thresholds, not exact execution times. Poll handles much I/O completion, while setImmediate callbacks run in check. libuv behavior has changed across releases, so do not rely on memorized top-level timer ordering. 042How do process.nextTick and promise microtasks interact?
Output

In ordinary top-level CommonJS execution, Node drains nextTick callbacks before promise microtasks after the current operation. 043When do you use worker threads, processes or ordinary async I/O?
Concept

Coordinate job state transitions atomically and design leases or visibility timeouts for worker failure. Add tenant-aware quotas, authorization, tracing and safe deployment/draining. Treat delivery guarantees as end-to-end properties, not labels that remove the need to reason about duplicate side effects.

/**
 * Senior JavaScript interview coding lab. No dependencies. Node.js 22+ for tests.
 * Each helper has a deliberately explicit contract; these are reference
 * implementations, not a claim to cover every application requirement.
 */
const MAX_DELAY = 2 ** 31 - 1;
const realScheduler = { setTimeout: (...a) => setTimeout(...a), clearTimeout: id => clearTimeout(id) };
function assertFunction(fn, name) {
  if (typeof fn !== 'function') throw new TypeError(`${name} must be a function`);
}
function assertDelay(value, name) {
  if (!Number.isFinite(value) || value < 0 || value > MAX_DELAY) {
    throw new RangeError(`${name} must be between 0 and ${MAX_DELAY}`);
  }
}
function checkAbort(signal) {
  if (signal?.aborted) throw signal.reason ?? new Error('Operation aborted');
}

/**
 * Trailing-only debounce. Calls return undefined; flush() returns the invoked
 * function's value (or promise). No leading edge, maxWait, or promise aggregation.
 * Timer-triggered exceptions follow the host's normal uncaught-error behavior;
 * async callback failures must be handled by the callback/owner.
 * @param {Function} fn
 * @param {number} wait
 * @param {{setTimeout: Function, clearTimeout: Function}} scheduler
 */
export function debounce(fn, wait, scheduler = realScheduler) {
  assertFunction(fn, 'fn');
  assertDelay(wait, 'wait');
  let timer = null, lastArgs, lastThis;
  const invoke = () => {
    const args = lastArgs, receiver = lastThis;
    timer = null;
    lastArgs = lastThis = undefined; // Clear before invocation: safe for reentrancy.
    return Reflect.apply(fn, receiver, args);
  };
  function wrapped(...args) {
    if (timer !== null) scheduler.clearTimeout(timer);
    lastArgs = args;
    lastThis = this;
    timer = scheduler.setTimeout(invoke, wait);
  }
  wrapped.cancel = () => {
    if (timer !== null) scheduler.clearTimeout(timer);
    timer = null;
    lastArgs = lastThis = undefined;
  };
  wrapped.flush = () => {
    if (timer === null) return undefined;
    scheduler.clearTimeout(timer);
    return invoke();
  };
  wrapped.pending = () => timer !== null;
  return wrapped;
}

/**
 * Ordered bounded-concurrency map over a finite array (snapshotted at entry).
 * mapper(value, index, signal) must cooperate with cancellation where possible.
 * On failure/cancellation: stop admission, signal started tasks, await their
 * settlement, then reject with the first observed reason (even undefined).
 * A non-cooperating operation that never settles can therefore prevent draining.
 * Memory: O(n) input/results plus O(limit) workers. This is not a streaming pool.
 * @template T,R
 * @param {T[]} items
 * @param {number} limit
 * @param {(value:T,index:number,signal:AbortSignal)=>R|Promise<R>} mapper
 * @param {{signal?:AbortSignal}} options
 * @returns {Promise<R[]>}
 */
export async function mapLimit(items, limit, mapper, { signal } = {}) {
  if (!Array.isArray(items)) throw new TypeError('items must be a finite array');
  if (!Number.isSafeInteger(limit) || limit < 1) throw new RangeError('limit must be a positive integer');
  assertFunction(mapper, 'mapper');
  checkAbort(signal);
  const input = Array.from(items), output = new Array(input.length);
  const controller = new AbortController();
  let next = 0, failed = false, firstError;
  const fail = reason => {
    if (failed) return;
    failed = true;
    firstError = reason;
    controller.abort(reason);
  };
  const onAbort = () => fail(signal.reason ?? new Error('Operation aborted'));
  signal?.addEventListener('abort', onAbort, { once: true });
  async function worker() {
    while (!failed) {
      const index = next++;
      if (index >= input.length) return;
      try { output[index] = await mapper(input[index], index, controller.signal); }
      catch (error) { fail(error); }
    }
  }
  try {
    await Promise.all(Array.from({ length: Math.min(limit, input.length) }, worker));
    if (failed) throw firstError;
    return output;
  } finally {
    signal?.removeEventListener('abort', onAbort);
  }
}

/** Entry-count-bounded LRU. No TTL, byte-size cap, deep cloning or cross-process coordination. */
export class LRUCache {
  #capacity;
  #data = new Map();
  constructor(capacity) {
    if (!Number.isSafeInteger(capacity) || capacity < 0) throw new RangeError('capacity must be a nonnegative integer');
    this.#capacity = capacity;
  }
  get size() { return this.#data.size; }
  has(key) { return this.#data.has(key); } // Does not promote.
  get(key) {
    if (!this.#data.has(key)) return undefined;
    const value = this.#data.get(key);
    this.#data.delete(key);
    this.#data.set(key, value);
    return value;
  }
  set(key, value) {
    if (this.#capacity === 0) return this;
    this.#data.delete(key);
    this.#data.set(key, value);
    if (this.#data.size > this.#capacity) {
      this.#data.delete(this.#data.keys().next().value);
    }
    return this;
  }
  delete(key) { return this.#data.delete(key); }
  clear() { this.#data.clear(); }
  entries() { return [...this.#data.entries()]; } // Least to most recently used.
}

/** Abortable delay. No event listeners or timers are retained after settlement. */
export function abortableSleep(ms, signal) {
  assertDelay(ms, 'ms');
  return new Promise((resolve, reject) => {
    if (signal?.aborted) { reject(signal.reason ?? new Error('Operation aborted')); return; }
    const cleanup = () => signal?.removeEventListener('abort', onAbort);
    const timer = setTimeout(() => { cleanup(); resolve(); }, ms);
    const onAbort = () => {
      clearTimeout(timer);
      cleanup();
      reject(signal.reason ?? new Error('Operation aborted'));
    };
    signal?.addEventListener('abort', onAbort, { once: true });
  });
}

/**
 * Bounded exponential-backoff retry with full jitter and cooperative cancellation.
 * The caller must explicitly classify retryable failures. Pass a deadline signal
 * and implement attempt timeouts in operation if required. No automatic HTTP
 * Retry-After parsing or idempotency guarantee is claimed.
 */
export async function retry(operation, {
  attempts = 3, baseMs = 100, maxMs = 5000, signal,
  shouldRetry = () => false, random = Math.random, sleep = abortableSleep
} = {}) {
  assertFunction(operation, 'operation');
  assertFunction(shouldRetry, 'shouldRetry');
  assertFunction(random, 'random');
  assertFunction(sleep, 'sleep');
  if (!Number.isSafeInteger(attempts) || attempts < 1) throw new RangeError('attempts must be positive');
  assertDelay(baseMs, 'baseMs');
  assertDelay(maxMs, 'maxMs');
  let cap = Math.min(baseMs, maxMs);
  for (let attempt = 1; attempt <= attempts; attempt++) {
    checkAbort(signal);
    try {
      const value = await operation({ attempt, signal });
      checkAbort(signal);
      return value;
    } catch (error) {
      checkAbort(signal);
      if (attempt === attempts || !shouldRetry(error, attempt)) throw error;
      const unit = random();
      if (!Number.isFinite(unit) || unit < 0 || unit >= 1) throw new RangeError('random must return [0,1)');
      await sleep(Math.floor(unit * cap), signal);
      cap = Math.min(maxMs, cap * 2);
    }
  }
}

/**
 * Deduplicate only IN-FLIGHT calls. Successful values are not persistently cached.
 * keyFn must encode all relevant arguments, tenant and authorization boundaries.
 * Shared operations have one owner: no per-subscriber abort semantics are added.
 * Outstanding entries are capped; a never-settling operation retains its entry.
 */
export function dedupeInFlight(fn, keyFn, { maxEntries = 256 } = {}) {
  assertFunction(fn, 'fn');
  assertFunction(keyFn, 'keyFn');
  if (!Number.isSafeInteger(maxEntries) || maxEntries < 1) throw new RangeError('maxEntries must be positive');
  const pending = new Map();
  return function (...args) {
    const key = Reflect.apply(keyFn, this, args);
    if (pending.has(key)) return pending.get(key);
    if (pending.size >= maxEntries) return Promise.reject(new Error('In-flight capacity exceeded'));
    const receiver = this;
    const promise = Promise.resolve().then(() => Reflect.apply(fn, receiver, args));
    pending.set(key, promise);
    const remove = () => { if (pending.get(key) === promise) pending.delete(key); };
    promise.then(remove, remove); // Both handlers return normally: no stray rejected child.
    return promise;
  };
}

/**
 * Small synchronous emitter. Registration order; duplicate registrations allowed;
 * current emission uses a snapshot; thrown errors stop that emission and propagate.
 * Async return values are not awaited; async listeners own their rejection policy.
 * Unlike Node EventEmitter, the event named 'error' has no special semantics.
 */
export class Emitter {
  #events = new Map();
  on(event, listener, { once = false } = {}) {
    assertFunction(listener, 'listener');
    let records = this.#events.get(event);
    if (!records) this.#events.set(event, records = new Set());
    const record = { listener, once, fired: false };
    records.add(record);
    const off = () => {
      records.delete(record);
      if (records.size === 0 && this.#events.get(event) === records) this.#events.delete(event);
    };
    record.off = off;
    return off;
  }
  once(event, listener) { return this.on(event, listener, { once: true }); }
  emit(event, ...args) {
    const records = [...(this.#events.get(event) ?? [])];
    for (const record of records) {
      if (record.once) {
        if (record.fired) continue;
        record.fired = true;
        record.off();
      }
      Reflect.apply(record.listener, undefined, args);
    }
    return records.length > 0;
  }
  listenerCount(event) { return this.#events.get(event)?.size ?? 0; }
}
