001How would you implement an O(1) LRU cache?Illustrated

Coding · Model answer

Use a hash map from keys to nodes plus a doubly linked list ordered by recency. A hit or update moves its node to the most-recent end; insertion over capacity removes the least-recent node and its map entry. Lookup, insertion and eviction are expected O(1), with O(capacity) storage. Specify capacity, missing-key behavior and synchronization. A production cache may also need byte limits and expiration; LRU alone supplies neither.

Senior signalExplain why an ordinary array requires shifting or searching, and test eviction after an existing key is read.
Worked example
from collections import OrderedDict
from threading import Lock
from typing import Generic, TypeVar

K = TypeVar("K")
V = TypeVar("V")

class LRUCache(Generic[K, V]):
    """Thread-safe, entry-count-bounded LRU; no TTL or cross-process sharing.

    get() raises KeyError on a miss. Expected O(1) get/put, O(capacity) space.
    The lock protects each operation, not a sequence of caller operations.
    """

    def __init__(self, capacity: int) -> None:
        if capacity < 1:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self._items: OrderedDict[K, V] = OrderedDict()
        self._lock = Lock()

    def get(self, key: K) -> V:
        with self._lock:
            value = self._items[key]
            self._items.move_to_end(key)
            return value

    def put(self, key: K, value: V) -> None:
        with self._lock:
            self._items[key] = value
            self._items.move_to_end(key)
            if len(self._items) > self.capacity:
                self._items.popitem(last=False)

    def __len__(self) -> int:
        with self._lock:
            return len(self._items)

002How do concurrency, parallelism and asynchronous I/O differ?Illustrated

Concept · Model answer

Concurrency means multiple tasks can make progress during overlapping lifetimes; parallelism means work executes at the same instant on multiple execution resources. Asynchronous I/O avoids occupying an execution thread while waiting, but does not make CPU-heavy instructions free. Choose the model by measured workload: many waiting requests favor async I/O or lightweight threads; CPU-heavy tasks need bounded parallel execution and enough cores. Include queue capacity, downstream limits and cancellation in the design.

Senior signalDo not assume that adding async to a function makes its synchronous CPU work run elsewhere.
Node.js: do not block the event loopOpenJDK JEP 444: virtual threads
003Why can an async Node.js handler still block the service?Illustrated

Debugging · Model answer

An async function runs synchronous work on the event-loop thread until it yields, and resumes synchronous work there afterward. Large JSON operations, expensive regular expressions or CPU-heavy loops can delay unrelated requests. Profile event-loop delay and CPU stacks; bound input size, stream or partition suitable work, and move substantial CPU work to a bounded worker-thread pool or a separate service. Adding await around an already synchronous calculation does not relocate that calculation.

Senior signalSeparate event-loop blocking from saturation of the runtime worker pool or the database.
Node.js: do not block the event loop
004When do Java virtual threads help, and what do they not solve?

Modern runtime · Model answer

Virtual threads help high-concurrency workloads that spend much of their time waiting, allowing a thread-per-task style without an operating-system thread per task. They do not execute CPU-bound code faster and cannot increase database capacity. Use a semaphore or another explicit limit around scarce resources instead of pooling virtual threads to limit concurrency. Validate behavior with the exact JDK and libraries in use; older advice about runtime limitations may not apply unchanged.

Senior signalTie the benefit to waiting time and throughput rather than claiming universal lower latency.
OpenJDK JEP 444: virtual threads
005How do you design bounded fan-out and cancellation?Illustrated

Coding · Model answer

Give the request an overall deadline, cap simultaneous downstream work, and define whether a partial result is acceptable. Propagate cancellation and release permits and connections in finally blocks. With structured concurrency, child tasks belong to a parent scope rather than surviving invisibly after it ends. A semaphore bounds active work, but creating millions of waiting tasks still consumes memory; use a bounded queue and fixed workers for unbounded inputs. Cancellation is cooperative, not a rollback of remote side effects.

Senior signalDistinguish a concurrency limit from a rate limit, and distinguish cancellation from transaction undo.
Worked example
import asyncio
from collections.abc import AsyncIterable, Awaitable, Callable
from typing import TypeVar, cast

T = TypeVar("T")

async def process_stream(
    items: AsyncIterable[T],
    work: Callable[[T], Awaitable[None]],
    *,
    workers: int = 8,
) -> None:
    """Process a stream with bounded tasks, queue size and active operations.

    A failed producer/worker cancels sibling tasks through TaskGroup.
    Cancellation remains cooperative: work() must not block the event loop
    or suppress cancellation. This function does not promise atomic effects.
    Use `async with asyncio.timeout(seconds):` around a call for a deadline.
    """
    if workers < 1:
        raise ValueError("workers must be positive")
    queue: asyncio.Queue[object] = asyncio.Queue(maxsize=2 * workers)
    stop = object()

    async def produce() -> None:
        async for item in items:
            await queue.put(item)  # Backpressure reaches the producer.
        for _ in range(workers):
            await queue.put(stop)

    async def consume() -> None:
        while True:
            item = await queue.get()
            try:
                if item is stop:
                    return
                await work(cast(T, item))
            finally:
                queue.task_done()

    async with asyncio.TaskGroup() as group:
        group.create_task(produce())
        for _ in range(workers):
            group.create_task(consume())

006Why is check-then-act unsafe under concurrency?

Code review · Model answer

Two workers can both observe an old value and act before either publishes its update. Protect the whole invariant, not just individual reads or writes: use an atomic operation, a lock with the right scope, or a conditional database update with a version predicate. A process-local mutex does not coordinate separate service replicas. Keep critical sections short and avoid external calls while holding a lock. Tests should force competing operations rather than depend on a race happening accidentally.

Senior signalState the ownership boundary: thread, process, host or distributed data store.

WHERE id = :id AND version = :expected_version
RETURNING id, version;

007Why can making the connection pool larger make latency worse?

Performance · Model answer

A pool is a concurrency control, not free capacity. More connections can increase database contention, memory pressure and time spent waiting inside the server. Measure pool wait, active queries, query duration, locks and server saturation separately. Set a global connection budget across the maximum number of application replicas, including rollout surge. Keep transactions short and apply acquisition deadlines. Increase the pool only when measurements show that the backend can use additional concurrent work productively.

Senior signalReason about queue placement and the total budget across replicas, not a per-instance default.
Google SRE: handling overload
008How would you investigate a growing memory footprint?

Debugging · Model answer

First separate managed heap, native allocations, memory-mapped data and container accounting. Compare heap profiles across representative load and inspect retained objects, unbounded caches, listeners, queues and per-request references. Correlate growth with traffic and garbage-collection behavior; high RSS alone does not prove a leak. Use a canary or safe replica for intrusive profiling because heap snapshots may pause execution and expose sensitive data. Fix retention or backpressure before simply raising the memory limit.

Senior signalExplain how you would distinguish a bounded warm cache from memory that grows without a stable ceiling.
Node.js: understanding and tuning memory
009How do dependency inversion and clean boundaries help a backend?

Design · Model answer

Keep business rules dependent on small domain-facing interfaces rather than concrete HTTP clients or database drivers. Construct implementations at the application boundary and test the domain without network infrastructure. Do not build an interface for every class: introduce a boundary where a policy, external dependency or meaningful substitution warrants it. Transactions and error semantics must remain explicit so abstractions do not conceal critical consistency behavior. Prefer cohesive modules to a large framework of generic base classes.

010How do you find the top K items from a large stream?Illustrated

Coding · Model answer

For the largest K values, maintain a min-heap of size at most K: insert until full, then replace the root only when the new value is larger. This costs O(n log K) time and O(K) memory, followed by O(K log K) if sorted output is required. Clarify whether K means individual records or most frequent distinct keys; frequency counting needs additional state or an approximate streaming algorithm. Handle K <= 0, duplicates and tie rules explicitly.

Senior signalState both time and space complexity, and clarify whether exact frequencies or approximate heavy hitters are required.
Worked example
import heapq
from collections.abc import Iterable

def largest_k(values: Iterable[int], k: int) -> list[int]:
    """Return up to k largest values, descending, preserving duplicates.

    O(n log(k+1) + k log(k+1)) time, O(k) auxiliary memory.
    A streaming input is consumed once; k=0 does not consume it.
    """
    if k < 0:
        raise ValueError("k cannot be negative")
    if k == 0:
        return []
    heap: list[int] = []
    for value in values:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)

CHAPTER 02APIs & application security

QUESTIONS 11-20
011What does HTTP idempotency mean, and does it imply identical responses?

API design · Model answer

An operation is idempotent when repeating the same request has the same intended server-side effect as making it once. It does not require identical response codes: repeating a DELETE may report that the resource is already absent. HTTP defines methods such as PUT and DELETE as idempotent; POST is not inherently idempotent. Implementation must respect the method semantics. A non-idempotent business action can expose a separate idempotency-key contract for safe retries.

Senior signalDo not confuse safe methods, idempotent effects and cacheable responses.
IETF RFC 9110: HTTP semantics
012How would you make a payment-creation API safe to retry?Illustrated

Scenario · Model answer

Require a client-generated idempotency key scoped to the caller and operation. Store a canonical request fingerprint, processing state and outcome behind a uniqueness constraint. Reject the same key with a different payload and coordinate concurrent duplicates. Couple local records to durable work and use the payment provider's idempotency mechanism for external charging. A crash after a remote charge needs reconciliation, not a blind new charge. Document key retention, retry windows and pending-response behavior.

Senior signalExplicitly address the crash between an external side effect and recording its result locally.
AWS Builders Library: making retries safe with idempotent APIs
013How do you choose REST, gRPC or GraphQL?

API design · Model answer

Choose by consumers and access patterns rather than fashion. Resource-oriented HTTP APIs are convenient for broad interoperability and standard HTTP tooling. gRPC suits strongly typed service contracts and streaming, but client and proxy support must be checked. GraphQL gives clients flexible data selection while requiring field-level authorization, query-cost controls and protection against N+1 access. None removes deadlines, pagination, compatibility testing or observability. Mixed interfaces can be reasonable when their operational cost is justified.

Senior signalDiscuss the consumer ecosystem, not just serialization benchmarks.
gRPC: core concepts
014How do you implement stable cursor pagination?Illustrated

Coding · Model answer

Use a deterministic sort with a unique tie-breaker, such as created_at DESC, id DESC, and encode the last tuple into an opaque cursor. Query strictly after that tuple in the matching direction with a suitable index. Bind the cursor to filters and tenant context and validate or authenticate it. A cursor avoids deep OFFSET scans and position shifts but does not automatically create a consistent snapshot across requests. Define how inserts, deletes and changes to sort keys affect traversal.

Senior signalA timestamp alone is not a unique ordering key; discuss snapshot requirements separately.
Worked example
-- Assumptions: created_at and id are NOT NULL; id is unique.
-- Keep filters and ordering stable across pages. Use an opaque cursor
-- containing both last_created_at and last_id.
SELECT id, created_at, title
FROM posts
WHERE tenant_id = :tenant_id
  AND (created_at, id) < (:last_created_at, :last_id)
ORDER BY created_at DESC, id DESC
LIMIT :page_size;
-- First page omits the cursor predicate. Validate page_size.
-- Useful index: (tenant_id, created_at DESC, id DESC).

015How do authentication, authorization and tenant isolation differ?Illustrated

Security · Model answer

Authentication establishes an identity; authorization decides whether that identity may perform an action on a particular resource. For multi-tenant APIs, derive the tenant from trusted identity context and enforce ownership or policy on every object access, including nested resources and bulk endpoints. Do not trust a tenant ID merely because the client sent it, and do not mistake an unguessable UUID for access control. Test cross-tenant reads, writes, exports and background jobs.

Senior signalCheck object-level and property-level permissions, not just whether the user has logged in.
OWASP: API Security Top 10, 2023 edition
016What must a backend validate before trusting a JWT?

Security · Model answer

Verify the cryptographic signature using trusted keys and an explicit accepted-algorithm policy. Validate issuer, intended audience, expiration and other applicable time and token-type rules. Treat the result as identity or claims input to authorization, not a universal permission grant. JWT payloads are usually encoded rather than encrypted, so avoid secrets in them. Plan key rotation, revocation or short lifetimes, and prevent access tokens from being accepted where a different token type is required.

Senior signalDecoding a JWT is not verification; signature validity alone is not audience validity.
IETF RFC 8725: JSON Web Token best current practices
017What OAuth guidance should a senior developer know now?

Modern security · Model answer

Use the authorization-code flow with PKCE for modern interactive clients and exact redirect-URI validation. OAuth grants authorization; OpenID Connect adds an identity layer for login. RFC 9700 consolidates security guidance and rejects the resource-owner password grant; implicit access-token delivery should not be a default for new designs. Restrict token audience and privileges, protect refresh tokens, and use sender constraints or rotation as appropriate. A client secret embedded in a public client is not a dependable secret.

Senior signalExplain why PKCE protects the code exchange and why token storage still matters.
IETF RFC 9700: OAuth 2.0 security best current practice
018How do you defend a URL-fetching endpoint against SSRF?Illustrated

Security · Model answer

Prefer an explicit destination allowlist and a constrained fetch service. Parse URLs with a trusted parser, restrict schemes and ports, resolve and validate destinations, and handle every redirect under the same policy. Block unauthorized loopback, private, link-local and metadata destinations across IPv4 and IPv6; account for DNS rebinding and egress proxies. Enforce network-level egress restrictions, response-size limits and timeouts. A string check for localhost or an HTTPS-only rule is insufficient.

Senior signalExplain how redirects and DNS changes can bypass a naive initial check.
OWASP: SSRF prevention
019How would you design a distributed rate limiter?Illustrated

Design · Model answer

First specify identity, fairness, burst allowance, time window and acceptable approximation. A token bucket limits average rate while permitting bounded bursts; a concurrency limiter protects in-flight resource use. For shared counters, update state atomically in a store with suitable consistency, expiration and clock behavior. Use tenant and global budgets, communicate throttling clearly, and decide fail-open versus fail-closed based on abuse and availability risk. A per-process limiter multiplies the effective quota as replicas grow.

Senior signalState the trade-off between global accuracy, latency, availability and regional independence.
AWS API Gateway: token-bucket throttling
020What is the difference between no-cache and no-store?

Caching · Model answer

Cache-Control: no-cache allows storage but requires validation before a stored response is reused. no-store instructs caches not to store the response. Use validators such as ETag for conditional requests where reuse is safe, and configure Vary and cache keys to match representation differences. For personalized or sensitive responses, prevent accidental shared-cache reuse and consider no-store as required. Caching policy is not authorization, and clearing or revoking existing cached data needs separate consideration.

Senior signalDo not teach no-cache as meaning never store, and do not ignore personalized response boundaries.
IETF RFC 9111: HTTP caching

CHAPTER 03SQL, databases & data modeling

QUESTIONS 21-30
021When would you choose SQL over a document or key-value database?

Trade-off · Model answer

Start with access patterns, invariants, query flexibility and operational constraints. Relational systems fit joins, constraints and multi-record transactions well; document or key-value models can fit aggregate-oriented access and predictable partition-key lookups. Do not equate NoSQL with no transactions or SQL with no horizontal scaling. Evaluate each product's actual guarantees, indexing, hot-partition limits, recovery and cost. A proposed choice should include representative queries and failure behavior, not only a technology label.

Senior signalMake the decision from data relationships and consistency requirements before discussing brand names.
PostgreSQL: constraintsAWS: DynamoDB read consistency
022How do you balance normalization, denormalization and constraints?

Data modeling · Model answer

Normalize authoritative data to avoid contradictory copies and update anomalies. Denormalize specific read models when measured access patterns justify the extra synchronization work. Keep business invariants in database constraints where possible, including uniqueness, foreign keys and suitable checks, while also validating inputs for useful errors. Define how derived copies are rebuilt and how stale they may be. Remember that a CHECK expression that evaluates to NULL does not replace a NOT NULL constraint in PostgreSQL.

Senior signalName which copy is authoritative and explain how denormalized data is repaired.
PostgreSQL: constraints
023How do you choose the column order in a composite index?Illustrated

SQL tuning · Model answer

Design the index around actual filters, range predicates and sort requirements. For a query filtering tenant_id by equality and ordering created_at and id descending, an index beginning with tenant_id followed by those ordering keys is a strong candidate. Check selectivity, statistics, index size and write amplification, then inspect the plan. Leading columns often determine efficiency, but avoid the absolute claim that a B-tree can never use a later column; supported planners may use other strategies.

Senior signalPropose an index for a concrete query and explain how you will validate it.
PostgreSQL: multicolumn indexes
024How would you investigate a slow database endpoint?

Debugging · Model answer

Start with traces and query counts so you can distinguish one slow query from N+1 queries or pool waiting. Use EXPLAIN to inspect the plan, and EXPLAIN (ANALYZE, BUFFERS) in a safe setting for actual behavior. Compare estimated and actual rows, access paths, join choices, loops, sorts, spills and I/O. ANALYZE executes the statement; do not casually run it on destructive production SQL. Correct statistics, query shape or indexes before assuming that a larger instance is the answer.

Senior signalMeasure complete request latency, not only one SQL duration.
PostgreSQL: using EXPLAIN
025What do isolation levels guarantee, and how do you handle serialization failures?Illustrated

Correctness · Model answer

Isolation levels constrain which interactions among concurrent transactions are allowed; exact behavior is database-specific. PostgreSQL Read Committed uses a fresh snapshot for each statement, while Repeatable Read provides a stable transaction snapshot but can still allow serialization anomalies. Serializable detects unsafe concurrent outcomes and may abort a transaction. Retry the entire transaction from a new snapshot with bounded attempts and jitter. Keep external side effects outside retried transaction bodies unless they have their own reliable idempotency.

Senior signalSerializable does not mean no retries, and repeatable reads do not imply every business invariant is safe.
PostgreSQL: transaction isolation
026How do you prevent inventory from being oversold?Illustrated

Coding · Model answer

For a simple single-row reservation, validate a positive requested quantity and atomically decrement only when enough stock remains: UPDATE inventory SET available = available - :qty WHERE sku = :sku AND available >= :qty RETURNING available. Treat zero returned rows as a failed reservation. Commit the reservation and order record together when they share a database. Multi-item orders need consistent locking or transactional logic, and retries need a unique operation identity to avoid reserving twice.

Senior signalExplain why a separate SELECT followed by an unconditional UPDATE leaves a race.

027How do you return the latest row for each customer?

SQL coding · Model answer

Use ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at DESC, id DESC) and select rn = 1 in an outer query. The unique tie-breaker makes the choice deterministic when timestamps match. Clarify whether the business wants exactly one row or all tied latest rows; the latter requires different ranking semantics. Indexing and data volume determine cost, so inspect the plan rather than assuming a window function is always optimal.

Senior signalExplain ROW_NUMBER versus RANK or DENSE_RANK when ties matter.
Worked example
-- Assumptions: created_at is NOT NULL and id uniquely breaks ties.
SELECT id, customer_id, created_at, total
FROM (
    SELECT id, customer_id, created_at, total,
           ROW_NUMBER() OVER (
               PARTITION BY customer_id
               ORDER BY created_at DESC, id DESC
           ) AS rn
    FROM orders
) AS ranked
WHERE rn = 1;
PostgreSQL: window functions
028How do you diagnose and reduce deadlocks?Illustrated

Debugging · Model answer

A deadlock occurs when transactions wait on each other in a cycle. Inspect the database deadlock report and the statements and locks involved. Acquire related rows in a consistent order, keep transactions short, use appropriate indexes, and avoid user interaction or remote calls while holding locks. The database may abort a participant; retry that complete transaction safely. A lock timeout bounds waiting but does not remove the underlying lock-order problem.

Senior signalDistinguish deadlock cycles from a long but acyclic lock wait.
PostgreSQL: explicit locking
029How do you evolve a large database schema without avoidable downtime?Illustrated

Deployment · Model answer

Use expand-and-contract: add a backward-compatible shape, deploy code that tolerates old and new data, backfill in bounded resumable batches, validate, switch readers or writers, then remove the obsolete shape after the rollback window. Inspect each migration's locking and rewrite behavior. PostgreSQL concurrent index builds avoid blocking ordinary writes for the whole build, but have restrictions, extra work and possible invalid-index cleanup. Do not combine a destructive rename and incompatible application rollout as a single blind step.

Senior signalInclude backfill load, old application versions, rollback compatibility and cleanup ownership.

030What do read replicas solve, and what can replication lag break?

Reliability · Model answer

Read replicas can offload eligible reads and support recovery strategies, but asynchronous replication can return stale data and lose recent acknowledged writes after failover. Route read-your-writes flows to the primary or use a verified replication-position mechanism; do not rely on an arbitrary sleep as a guarantee. Define acceptable staleness per operation, monitor lag and test promotion and fencing. A replica is not a backup because accidental deletes and corruption can also propagate.

Senior signalSeparate read scaling, high availability and point-in-time recovery.

QUESTIONS 31-40
031What does CAP actually say during a network partition?

Concept · Model answer

Under a partition, a distributed service cannot guarantee both linearizable behavior and a successful response from every non-failing node for every request. CAP availability is a formal property, not the same as an uptime percentage. A consistency-preserving system may reject or delay some operations; an availability-oriented one may accept divergent state and reconcile. The decision can vary by operation. Outside partitions, latency and coordination still affect design, so pick two is an inadequate architecture method.

Senior signalDescribe a partition scenario and the observable behavior rather than assigning a whole product a permanent label.
IBM Cloudant: CAP theorem and consistency trade-offs
032What problem does the transactional outbox solve?Illustrated

Architecture · Model answer

Writing business data and then publishing an event to a separate broker creates a dual-write failure window. Instead, commit the business change and an outbox row in one local database transaction. A relay or change-data-capture process publishes committed events and retries failures. Publishing can be duplicated if the relay crashes after send but before marking progress, so consumers need durable idempotency. Monitor relay lag, define event ordering per aggregate and retain enough history for recovery.

Senior signalThe outbox makes local state and publication intent atomic; it does not make delivery globally exactly once.
AWS Prescriptive Guidance: transactional outbox
033What is a saga, and how does compensation differ from rollback?Illustrated

Architecture · Model answer

A saga coordinates a business workflow through local transactions and subsequent actions. When a later step fails, compensations attempt to restore a business-acceptable state, such as releasing inventory or issuing a refund. Compensation is not database rollback: time has passed, other actors may have observed the effects, and refunds or cancellations can also fail. Make steps and compensations idempotent, persist workflow state, handle timeouts and provide reconciliation or manual review for unresolved states.

Senior signalSpecify an irreversible step and how the workflow responds when its compensation cannot complete.
AWS Prescriptive Guidance: saga patterns
034What does exactly-once processing mean at a system boundary?

Messaging · Model answer

At-most-once handling can lose work; at-least-once handling can repeat it. Exactly-once claims must identify the transaction boundary and failure assumptions. Kafka transactions can atomically connect consumed offsets and produced Kafka records, with suitable consumer isolation. They do not automatically make an unrelated payment API or database update exactly once. For an external database, combine a durable event-identity record and the local business mutation in one transaction; acknowledge afterward and handle replay safely.

Senior signalAsk exactly once where, and for which observable side effect?
Apache Kafka: KIP-98, transactional messaging
035How do Kafka partitions, ordering and consumer groups interact?Illustrated

Messaging · Model answer

Kafka ordering is per partition, not a global order across an entire topic. Generally no. A percentile is not an additive quantity, and instance percentiles cannot reconstruct the combined request distribution, especially when traffic volumes differ. Aggregate compatible histogram observations or bucket counts over the desired interval and compute the fleet quantile from that distribution. Understand bucket resolution and aggregation rules; client-calculated summary quantiles cannot simply be averaged into a global percentile. Inspect tail behavior by meaningful request classes as well as a global view.

Senior signalDistinguish combining underlying observations from combining already-calculated quantiles.
Prometheus: histograms and summaries
086What should a senior engineer do in the first minutes of an incident?

Incident response · Model answer

Confirm impact, declare the incident when warranted and establish an incident lead, communication channel and shared timeline. Prioritize safe mitigation: stop a rollout, reduce load, disable a problematic path or fail over only when its prerequisites are understood. Delegate diagnosis and communication, record decisions and preserve useful evidence. Avoid many uncoordinated changes and do not wait for a perfect root-cause explanation before reducing customer harm. State uncertainty clearly and update stakeholders on known impact.

Senior signalExplain your mitigation decision, its risk and how you verify recovery.
Google SRE: managing incidents
087How do you know a backup strategy actually works?Illustrated

Recovery · Model answer

A successful backup job is only one signal. Restore backups into an isolated environment on a schedule, verify integrity and application-level correctness, and measure achieved recovery time and recovered data age. Include encryption keys, permissions, configuration and dependent services. Test point-in-time recovery and accidental-delete scenarios where appropriate. Use separation and immutability against correlated loss, and retain evidence of drills. Replication alone is insufficient because unwanted changes can propagate to replicas.

Senior signalDescribe a restore drill and its acceptance criteria, not just the backup schedule.
Google SRE: data integrity and recovery
088How do you design a useful load test?

Performance testing · Model answer

Model realistic request mixes, payloads, arrival rates, data sizes and dependency behavior. Measure throughput, errors, latency distributions, queues and resource saturation, with warmup and sustained runs. Distinguish constant-concurrency clients from constant-arrival-rate load; clients that wait for slow responses can unintentionally reduce offered load and hide bad periods. Confirm the load generator is not the bottleneck. Include overload behavior and recovery, not just the highest transient requests-per-second number.

Senior signalExplain the workload model and how you avoid a test that becomes gentler as the service slows.
Grafana k6: open versus closed workload models
089How would you run a safe failure-injection experiment?

Resilience testing · Model answer

Define a falsifiable hypothesis, a steady-state user measure and a narrowly scoped fault such as dependency delay or a single replica loss. Start in a safe environment or a tiny production scope with explicit authorization, monitoring, rollback and abort thresholds. Check that the fault was actually injected and measure recovery as well as impact. Expand only after learning from prior runs. Randomly destroying production resources without a hypothesis and containment plan is not responsible resilience testing.

Senior signalName the blast radius, stop condition and learning objective before the fault.
Principles of Chaos Engineering
090What makes a postmortem useful and blameless?

Learning · Model answer

Document impact, a factual timeline, contributing conditions, detection and response gaps, and what worked. Explain why actions made sense with the information and incentives available rather than blaming an individual as the root cause. Assign a small set of concrete corrective actions with owners, priorities and verification. Blameless does not mean avoiding accountability: the team owns improving the system and completing agreed actions. Track whether recurrence risk or recovery time actually improves.

Senior signalPrefer a measurable system change over an action item that merely says be more careful.
Google SRE: postmortem culture

QUESTIONS 91-100
091What does a balanced backend test strategy look like?Illustrated

Testing strategy · Model answer

Use fast unit tests for domain behavior, integration tests for real storage and infrastructure semantics, contract tests for boundaries, and a focused set of end-to-end tests for critical journeys. Test failure paths, authorization and concurrency as well as happy paths. Mocks can isolate behavior but may encode assumptions that the real dependency violates; run representative tests against actual engines. Choose the mix by risk and feedback speed rather than forcing a fixed percentage pyramid onto every service.

Senior signalExplain which class of bug each test layer can detect and which it cannot.
Google SRE: testing for reliability
092How do you evolve an API or event schema without breaking consumers?Illustrated

Compatibility · Model answer

Identify producers and consumers, define compatibility rules and test both old and new combinations. Prefer additive optional fields, preserve meaning and tolerate unknown fields where the contract permits. Do not reuse a removed protocol field identifier for an unrelated meaning; reserve it where supported. Required-field changes, narrowing accepted values and new enum values can surprise consumers. Version only when necessary, support a transition window and measure adoption before removal. Wire compatibility is not identical to semantic compatibility.

Senior signalAn unchanged field type does not make a changed business meaning compatible.
Protocol Buffers: proto3 language guide
093What should a senior engineer prioritize in a code review?

Code review · Model answer

Review correctness and invariants, security, failure behavior, compatibility and operational visibility before stylistic preferences that tooling can enforce. Ask whether retries duplicate effects, transactions are bounded, inputs are authorized and failures are observable. Check tests for meaningful assertions and missing edge cases; coverage only measures executed code, not whether the behavior is correctly verified. Explain the reasoning behind blocking concerns, distinguish suggestions and avoid broad unrelated rewrites inside a focused change.

Senior signalName a concrete failure mode the review would prevent rather than merely saying clean code.
Google Engineering Practices: what to look for in a code review
094How do feature flags differ from deployments and rollbacks?Illustrated

Release design · Model answer

A deployment changes installed code; a feature flag can control exposure or behavior independently. Flags enable gradual rollout and fast mitigation when the disabled path remains safe. They introduce configuration, testing and cleanup obligations: test important combinations, control who changes them and remove expired flags. A flag cannot undo destructive schema changes or already completed external effects. Treat critical flag infrastructure and fallback values as part of the service's reliability design.

Senior signalSpecify the safe disabled behavior and an owner and removal date for temporary flags.
OpenFeature: introduction to feature flagging
095How do you handle an architecture disagreement?Illustrated

Leadership · Model answer

Restate the shared goal and constraints, document the competing options and separate evidence from preference. Compare correctness, delivery risk, operating burden, cost and reversibility. Propose a small experiment for the highest-impact uncertainty and record the decision and revisit trigger. Escalate when necessary using the agreed decision process, then support the chosen path. A strong interview answer describes your actual role and what you learned, not a story in which everyone else was simply wrong.

Senior signalShow how the disagreement became a decision with evidence and an explicit trade-off.
AWS Prescriptive Guidance: architectural decision records
096How do you mentor engineers without becoming a bottleneck?

Leadership · Model answer

Agree on a bounded stretch task, make the outcome and safety constraints explicit, and provide context and checkpoints rather than taking over every decision. Pair on difficult reasoning, review with explanations and gradually transfer ownership, including operational follow-through. Write down recurring knowledge and improve team tools so support scales beyond one person. Evaluate progress through independent judgment and delivered outcomes, not through the number of times the engineer follows your exact implementation preference.

Senior signalUse a truthful example showing another engineer's increasing ownership, not only your personal heroics.
Google Engineering Practices: constructive review comments
097How do you justify technical-debt work to product stakeholders?

Prioritization · Model answer

Describe the debt as an observable business or operating cost: incident risk, slow changes, support load or constrained growth. Estimate the cost of delay and compare a bounded improvement with alternatives and feature commitments. Include a baseline, expected benefit, delivery risk and a way to verify the result. Prefer incremental work where possible and revisit assumptions. Calling code ugly or requesting a complete rewrite without evidence is less persuasive than tying a targeted change to customer outcomes.

Senior signalPresent an explicit priority trade-off rather than assuming technical quality has unlimited budget.
Google SRE: eliminating toil
098What is a platform engineering golden path?

Platform engineering · Model answer

A golden path is a supported, documented route for common engineering work, such as creating and operating a service with approved build, deployment and observability defaults. Treat the platform as a product for internal users: gather feedback, make safe work easier and measure adoption and useful outcomes. Provide governed escape hatches for legitimate needs rather than forcing every workload into one template. A portal alone is not a platform if teams still perform the same manual coordination behind it.

Senior signalConnect self-service with ownership, support and feedback instead of describing only a tool catalog.
CNCF: platforms white paper
099How should AI-generated backend or infrastructure code be reviewed?

Modern engineering · Model answer

Apply the same ownership and quality bar as other code, with extra attention to plausible but incorrect APIs, insecure defaults, invented dependencies and hidden failure paths. Verify claims against authoritative documentation, inspect permissions and secrets, test behavior and run security checks in a safe environment. Do not give generated code unrestricted production execution because it looks convincing. Use approved data-handling practices and evaluate whether the tool improves complete delivery outcomes, not just initial code-generation speed.

Senior signalThe authoring tool does not transfer responsibility for correctness or production impact.
GitHub: responsible use of Copilot agents and code review
100How should you answer Tell me about a production incident you owned?Illustrated

Behavioral interview · Model answer

Use a real example and structure it as context and impact, your responsibility, decisions and trade-offs, mitigation, measured outcome and follow-up learning. Separate your actions from the team's work and state what you knew at each stage. Include a decision you would now improve and how the system changed afterward. Do not invent scale, savings or personal ownership; label estimates and unavailable measurements honestly. The goal is to demonstrate judgment, communication and learning, not flawless heroics.

Senior signalPrepare a truthful two-minute version and be ready to expand the technical and organizational details.
