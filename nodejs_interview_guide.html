SECTION 01 / QUESTIONS 001-010

Runtime and npm

001What is Node.js, and when is it a good fit?BeginnerConceptIllustrated
Interview answer

Node.js is a JavaScript runtime, not a language or a web framework. It combines the V8 engine with host APIs for networking, files, processes, and other server-side tasks. Its event-driven model is a good fit for I/O-heavy APIs, streaming services, real-time applications, command-line tools, and build tools.

Go one level deeperFor a CPU-heavy endpoint, explain how you would isolate the computation rather than claiming that Node.js cannot do it.
Common trap: Express is a framework running on Node.js; it is not Node.js itself.
Reference: Node.js official downloads and versions Do not block the event loop or worker pool
002Is Node.js single-threaded?BeginnerConceptIllustrated
Interview answer

JavaScript runs on one thread per isolate by default. The overall process is not limited to one thread: libuv, V8, native libraries, and worker threads can do work elsewhere. Concurrency means overlapping progress; parallelism means simultaneous execution on different execution resources.

Go one level deeperDiscuss the difference between handling many waiting sockets and executing several CPU-bound JavaScript functions at once.
Common trap: A single event loop does not mean the whole process contains one operating-system thread.
Reference: Node.js worker threads Do not block the event loop or worker pool
003What does libuv do, and which operations use its thread pool?IntermediateConceptIllustrated
Interview answer

libuv provides the event loop and cross-platform asynchronous I/O facilities. Many file-system operations, selected crypto operations, compression, and dns.lookup use its worker pool. Network sockets generally use operating-system readiness/completion mechanisms rather than assigning a pool thread to every connection.

Go one level deeperMeasure queueing and workload mix before changing UV_THREADPOOL_SIZE; additional threads can increase contention.
Common trap: Not all asynchronous APIs use the libuv pool, and the pool does not run arbitrary JavaScript.
Reference: Do not block the event loop or worker pool Node.js file system API
004What are Current and LTS, and which Node.js version should production use?BeginnerCurrent knowledgeIllustrated
Interview answer

As verified on 16 September 2026, the latest Current release is 26.8.2 and the latest LTS release is 24.21.0. Node.js 22 is also in LTS; Node.js 20 is end-of-life. The Node.js project recommends Active LTS or Maintenance LTS for production. Match the runtime to your application support policy, dependencies, and security updates.

Go one level deeperTreat version numbers as dated facts, not permanent interview answers. Recheck the release schedule before deploying.
Common trap: The highest major version is not automatically the recommended production baseline.
Reference: Node.js official downloads and versions Node.js release lifecycle Node.js 26.8.2 release notes Node.js 24.21.0 release notes
005How does Node.js differ from browser JavaScript?BeginnerComparisonIllustrated
Interview answer

The language is JavaScript in both environments, but the host APIs differ. Node.js provides APIs such as node:fs and node:net; a browser provides the DOM. Modern Node.js also includes several web-compatible APIs, such as fetch, URL, AbortController, and a WebSocket client. This does not make the two environments interchangeable.

Go one level deeperPrefer explicit imports and globalThis when writing environment-neutral code, and isolate platform-specific adapters.
Common trap: Do not assume window, document, or a browser cookie jar exists in a Node.js program.
Reference: Node.js global APIs Node.js official downloads and versions
006How do npm install and npm ci differ?BeginnerComparisonIllustrated
Interview answer

npm install resolves dependencies and may update the lockfile. npm ci requires a lockfile, rejects a mismatch with package.json, removes an existing node_modules directory, and installs without updating package manifests or the lockfile. Use npm ci for repeatable CI installations, with the same relevant configuration used to produce the lockfile.

Go one level deeperA repeatable dependency graph still needs a controlled Node.js version, package-manager version, platform, and install-script policy.
Common trap: npm ci is not a command for adding a new dependency.
Reference: npm ci documentation
007Why commit package-lock.json?BeginnerConceptIllustrated
Interview answer

It records the resolved dependency tree and integrity metadata so teammates and CI can install a consistent graph. package.json communicates declared requirements; the lockfile captures the actual resolution. Commit application lockfiles and review their changes alongside source changes.

Go one level deeperExplain why a lockfile improves repeatability without proving that every dependency is safe.
Common trap: Deleting the lockfile to silence a dependency problem changes the resolution rather than diagnosing the problem.
Reference: npm package-lock.json documentation npm ci documentation
008What are dependencies, devDependencies, and peerDependencies?BeginnerComparison
Interview answer

dependencies are packages needed by the delivered application or library at runtime. devDependencies are needed for development, testing, or building. peerDependencies express compatibility with a host package, such as a plugin and its framework. Modern npm can install peer dependencies automatically; peer does not simply mean "never installed."

Go one level deeperBuild before omitting development dependencies when the compiler or bundler is a devDependency.
Common trap: A package needed to run the deployed JavaScript must not disappear from the production installation.
Reference: npm package.json documentation
009How do semantic-version ranges work?BeginnerConcept
Interview answer

For normal stable versions, MAJOR communicates incompatible changes, MINOR adds backward-compatible functionality, and PATCH fixes bugs. npm ranges ^1.2.3 and ~1.2.3 normally allow versions below 2.0.0 and 1.3.0 respectively. Caret ranges for 0.x versions are narrower; prereleases also have special rules.

Go one level deeperA semver promise is made by a maintainer, so still test upgrades and review the lockfile.
Common trap: ^0.2.3 does not allow every later 0.x release.
Reference: npm semver implementation and range rules
010How should a Node.js application handle configuration and environment variables?BeginnerPractical
Interview answer

Read environment variables through process.env, parse them into the intended types, validate required values at startup, and fail clearly when configuration is invalid. Node.js provides native .env support through --env-file. Keep secrets out of the repository and logs, and use deployment secret facilities for sensitive values.

Go one level deeperTreat PORT="3000" as a string until validated and converted. Distinguish a missing variable from an explicitly empty one.
Common trap: Boolean("false") is true; string configuration needs explicit parsing.
Reference: Node.js environment variables Node.js command-line options
SECTION 02 / QUESTIONS 011-020

Async and the event loop

011What are the important event-loop phases?IntermediateConceptIllustrated
Interview answer

The main phases include timers, pending callbacks, poll, check, and close callbacks; idle/prepare phases are internal. Poll handles I/O callbacks, while check handles setImmediate callbacks. nextTick and Promise microtasks are not additional libuv phases. Since libuv 1.45 / Node.js 20, regular loop iterations process timers after poll, with an initial compatibility pass.

Go one level deeperExplain a concrete scheduling example instead of memorizing a diagram without callback context.
Common trap: A timer specifies a threshold, not an exact execution time.
Reference: Node.js event loop guide Node.js timers
012How do process.nextTick, queueMicrotask, and Promise callbacks differ?AdvancedComparisonIllustrated
Interview answer

process.nextTick uses a Node-specific queue; queueMicrotask and Promise reactions share the microtask queue. At CommonJS entry-point top level, nextTick callbacks drain before Promise microtasks. Top-level ESM is already evaluated in a microtask context, which can reverse that simple example. Repeated scheduling can starve I/O.

Go one level deeperFor portable deferred callbacks, prefer queueMicrotask when its semantics fit. State the module context before predicting order.
Common trap: "nextTick always runs before every Promise callback" is too broad.
Reference: Node.js process API
013Does setTimeout(fn, 0) always run before setImmediate(fn)?IntermediateComparisonIllustrated
Interview answer

No. At entry-point top level, their relative order is not guaranteed. When both are scheduled inside the same ordinary I/O callback, setImmediate runs before the newly scheduled timer. A zero delay does not mean the callback executes immediately or preempts current code.

Go one level deeperFor an output puzzle, first identify whether scheduling happens at top level, inside I/O, or inside another callback.
Common trap: Do not infer a guarantee from a single local run.
Reference: Node.js event loop guide Node.js timers
014What is an error-first callback, and how do you modernize it?BeginnerPractical
Interview answer

An error-first callback receives an error as its first argument and a result in a later argument, conventionally callback(err, value). Handle the error and return before using the value. Prefer an existing Promise API such as node:fs/promises; use util.promisify for compatible callback APIs, preserving this when a method needs it.

Go one level deeperDo not throw inside an asynchronous callback and expect an outer, already-completed try/catch to catch it.
Common trap: Promisifying an arbitrary callback shape can lose multiple results or break its receiver binding.
Reference: Node.js error handling conventions Node.js promisify and utility API
015Does async/await make a CPU-heavy function non-blocking?IntermediateConceptIllustrated
Interview answer

No. An async function returns a Promise, but its synchronous JavaScript still executes on the current thread. await suspends that function until its awaited value is settled; it does not automatically offload computation. Move substantial CPU work to worker threads or another service, or divide suitable work into bounded chunks.

Go one level deeperMaking JSON.parse run inside an async function does not make parsing a huge document asynchronous.
Common trap: A Promise is a completion abstraction, not a thread.
Reference: ECMAScript async function semantics Do not block the event loop or worker pool Node.js worker threads
016When should you use Promise.all, allSettled, race, and any?IntermediateComparisonIllustrated
Interview answer

all fulfills when every input fulfills and rejects on an input rejection. allSettled reports every outcome. race adopts the first settlement, whether fulfillment or rejection. any fulfills on the first fulfillment and rejects with AggregateError if all reject. Results from all and allSettled retain input order.

Go one level deeperChoose based on failure policy, then separately decide whether losing or unfinished work should be cancelled.
Common trap: Promise.all rejecting does not automatically cancel the other operations.
Reference: ECMAScript Promise specification
017Why does await items.forEach(async item => ...) not wait?IntermediateDebuggingIllustrated
Interview answer

forEach ignores the callback return values and returns undefined. Awaiting that undefined value does not await the callback Promises. Use for...of with await for sequential work, or await Promise.all(items.map(...)) for a small, bounded batch of independent work.

Go one level deeperFor a large input set, use a concurrency limiter instead of starting every request at once.
Common trap: An async callback does not change the contract of the function receiving it.
Reference: ECMAScript Array specification ECMAScript Promise specification
018How do you limit concurrency for thousands of asynchronous jobs?AdvancedDesignIllustrated
Interview answer

Use a fixed number of consumers that take jobs from a queue, or a tested concurrency limiter. Bound both active work and queued work, define timeout and cancellation policies, and preserve result order only when needed. Concurrency controls how many jobs are in flight; a rate limit controls how many begin per time interval.

Go one level deeperIn an interview, describe the maximum active jobs, queue capacity, failure behavior, and how you would verify the limit.
Common trap: Promise.all over 100,000 network calls is not a concurrency limit.
Reference: Node.js backpressure guide Microsoft retry pattern
019How does cancellation work with AbortController and AbortSignal?IntermediatePracticalIllustrated
Interview answer

Pass an AbortSignal to an API that supports it and abort the associated controller when the operation is no longer needed. AbortSignal.timeout creates a deadline signal; AbortSignal.any can combine caller cancellation and a timeout. Cancellation is cooperative and API-specific, not a way to interrupt arbitrary synchronous JavaScript.

Go one level deeperPropagate cancellation into downstream work and release resources. Check the particular API for its rejection or abort semantics.
Common trap: Timing out a Promise.race does not itself stop the losing network request.
Reference: Node.js global APIs Node.js fetch with Undici
020How should you handle uncaught exceptions and unhandled rejections?AdvancedIncident response
Interview answer

Handle expected failures at their operation boundaries. An uncaught exception signals an unsafe process state; record diagnostics, perform only safe synchronous last-resort cleanup, and let a supervisor restart the process. Do not install a catch-all handler merely to keep serving. Modern Node.js defaults unhandled rejections to throw behavior unless handling or flags alter it.

Go one level deeperDistinguish a controlled SIGTERM drain from recovery after an unknown, uncaught programming error.
Common trap: Logging a fatal error and continuing does not repair corrupted application state.
Reference: Node.js process API Node.js error handling conventions
SECTION 03 / QUESTIONS 021-030

Modules and TypeScript

021How do CommonJS and ES modules differ?BeginnerComparisonIllustrated
Interview answer

CommonJS uses require and module.exports, with synchronous loading semantics. ES modules use import and export, support static analysis and live bindings, and allow top-level await. Node.js supports both and provides interoperability, but default exports, named exports, loading, and caching details differ.

Go one level deeperFor a new project, make the module format explicit and check the formats of its dependencies.
Common trap: They are not merely two spellings with identical execution behavior.
Reference: Node.js CommonJS modules Node.js ECMAScript modules
022How does Node.js decide whether a file is CommonJS or ESM?BeginnerPracticalIllustrated
Interview answer

.mjs explicitly indicates ESM and .cjs explicitly indicates CommonJS. For .js, the nearest package.json type field provides an explicit choice: module or commonjs. Modern Node.js can inspect syntax in otherwise ambiguous JavaScript, but explicit configuration is more predictable. Normal relative ESM imports require file extensions.

Go one level deeperUse .mts and .cts for explicit TypeScript module formats when using native TypeScript support.
Common trap: A .js extension by itself is not a universal guarantee of CommonJS.
Reference: Node.js package configuration Node.js ECMAScript modules Node.js native TypeScript support
023What is the difference between exports and module.exports?BeginnerDebuggingIllustrated
Interview answer

In CommonJS, exports initially references the same object as module.exports. Adding exports.name mutates that object. Reassigning exports only changes the local variable and does not replace the exported value; assign module.exports to export a new object, class, or function.

Go one level deeperPredict what another file receives after exports = function () {}, and contrast it with module.exports = function () {}.
Common trap: exports is a convenience alias, not a magic setter.
Reference: Node.js CommonJS modules
024Can require load an ES module in modern Node.js?AdvancedCurrent knowledgeIllustrated
Interview answer

Yes, modern Node.js can require a qualifying synchronous ES module graph. If that graph contains top-level await, synchronous require cannot complete it; use dynamic import instead. This makes the older blanket statement "require can never load ESM" incorrect, but it does not remove every interoperability difference.

Go one level deeperCheck the exact runtime and the dependency graph, not just the extension of the entry file.
Common trap: Top-level await in an imported dependency matters too.
Reference: Node.js CommonJS modules Node.js ECMAScript modules
025What is top-level await, and what trade-off does it introduce?IntermediateConceptIllustrated
Interview answer

Top-level await allows an ES module to await initialization outside a function. Modules that depend on its evaluation must wait, which is useful for startup dependencies but can lengthen startup or complicate cycles. Avoid making every import unexpectedly depend on a slow network call.

Go one level deeperAn explicit async start function may make lifecycle and failure handling easier to test.
Common trap: Top-level await is not ordinary CommonJS syntax.
Reference: Node.js ECMAScript modules
026What do package.json exports and imports do?IntermediateConcept
Interview answer

exports defines a package's public entry points and can choose different targets under supported conditions. imports provides package-private aliases, typically starting with #. These fields make supported boundaries explicit and reduce reliance on internal file paths.

Go one level deeperWhen publishing dual-module packages, test both import and require consumers and avoid accidentally creating two independent singleton states.
Common trap: Adding an exports map can break consumers that used previously reachable internal paths.
Reference: Node.js package configuration
027When should you use dynamic import()?IntermediatePracticalIllustrated
Interview answer

Use dynamic import for conditional or lazy module loading, or to load ESM from CommonJS when asynchronous loading is acceptable. It returns a Promise for a module namespace. Handle load failures and keep the set of allowable modules controlled when a choice originates from user input.

Go one level deeperDistinguish loading a trusted plugin from executing arbitrary code supplied by a request.
Common trap: Dynamic import is asynchronous but is not a security sandbox.
Reference: Node.js ECMAScript modules Node.js Permission Model
028Can Node.js run TypeScript without a build step?IntermediateCurrent knowledgeIllustrated
Interview answer

Modern Node.js can run TypeScript containing supported erasable syntax by stripping types. It does not type-check, does not apply tsconfig.json transformations or path aliases, and does not support .tsx through this mechanism. Type stripping became stable in 24.12.0; Node.js 26 removed --experimental-transform-types. Use a compiler or suitable tooling when transformation is required.

Go one level deeperKeep a separate type-checking step such as tsc --noEmit in CI. Use import type for type-only imports.
Common trap: Native TypeScript execution is not full TypeScript compilation.
Reference: Node.js native TypeScript support Node.js 26.0.0 release notes
029Why validate runtime input when an application uses TypeScript?IntermediateSecurityIllustrated
Interview answer

TypeScript types do not enforce the shape of network requests, configuration, database records, or third-party responses at runtime. Treat these values as unknown, validate and constrain them at trust boundaries, and only then use a typed internal representation. Enforce authorization separately from shape validation.

Go one level deeperValidate size, allowed keys, ranges, formats, and semantic rules, not just whether a value is an object.
Common trap: A type assertion tells the compiler what to assume; it does not inspect a value.
Reference: Node.js native TypeScript support OWASP input validation
030How do module caching and circular dependencies affect application state?AdvancedDebugging
Interview answer

CommonJS caches modules by resolved filename, so repeated requires commonly share the same exported object. A cycle can expose partially initialized exports. ESM has its own loader cache and live-binding semantics; reading an uninitialized binding in a cycle can fail. Prefer explicit dependencies and factories when shared mutable module state becomes hard to reason about.

Go one level deeperIn tests, inject dependencies instead of relying on ad hoc cache deletion for isolation.
Common trap: Two differently resolved copies of a package need not share a singleton.
Reference: Node.js CommonJS modules Node.js ECMAScript modules
SECTION 04 / QUESTIONS 031-040

Core APIs and streams

031Are EventEmitter listeners asynchronous?BeginnerConceptIllustrated
Interview answer

Ordinary EventEmitter listeners are invoked synchronously in registration order when emit is called. A listener can start asynchronous work, but emit does not await the resulting Promise. Use an explicit Promise-based protocol when the caller must wait for all work to finish.

Go one level deeperExplain why a slow synchronous listener delays every subsequent listener and the code after emit.
Common trap: Event-driven does not mean every event listener runs asynchronously.
Reference: Node.js EventEmitter documentation
032What is special about the error event, and how do you avoid listener leaks?IntermediateDebuggingIllustrated
Interview answer

Emitting error without a corresponding regular error listener normally throws. Install purposeful error handling, use once for one-shot subscriptions, and remove listeners when their owners are disposed. A listener-count warning is a diagnostic signal to investigate ownership, not an instruction to raise the limit automatically.

Go one level deeperIf listeners are async, understand captureRejections or handle their rejections explicitly; neither replaces all error handling.
Common trap: Increasing setMaxListeners does not fix retained request objects or forgotten subscriptions.
Reference: Node.js EventEmitter documentation
033What is a Buffer, and how do alloc and allocUnsafe differ?BeginnerComparison
Interview answer

Buffer represents binary bytes and extends Uint8Array. Buffer.alloc(size) initializes bytes, usually to zero. Buffer.allocUnsafe(size) may expose previously used memory unless every byte is overwritten before it is read or sent. Use explicit encodings when converting text, and distinguish byte length from character count.

Go one level deeperRemember that a Buffer subarray shares underlying memory rather than producing an independent copy.
Common trap: UTF-8 text length is not necessarily the number of bytes required to encode it.
Reference: Node.js Buffer documentation
034What are the main Node.js stream types?BeginnerConceptIllustrated
Interview answer

Readable streams produce data; Writable streams consume it. Duplex streams can both read and write, while Transform streams are duplex streams whose output is derived from input, such as compression. Streams let a program process data incrementally rather than buffering the whole input.

Go one level deeperExplain whether the two sides of a Duplex stream are independent or related by a transformation.
Common trap: A stream does not guarantee bounded memory if your own code keeps accumulating chunks.
Reference: Node.js stream API
035What is backpressure, and what does write returning false mean?IntermediateConceptIllustrated
Interview answer

Backpressure is a signal from a slower consumer to a faster producer to avoid unbounded buffering. When writable.write returns false, stop adding chunks and resume after drain. highWaterMark is a buffering threshold, not a strict maximum allocation. Also handle errors, closure, and cancellation.

Go one level deeperDescribe memory growth when a producer ignores a slow network client or storage device.
Common trap: false from write does not mean the chunk was rejected and must be sent again.
Reference: Node.js backpressure guide Node.js stream API
036Why use pipeline instead of chaining pipe calls casually?IntermediatePracticalIllustrated
Interview answer

pipeline connects stages with coordinated completion, error propagation, and teardown. The Promise version from node:stream/promises can be awaited. It is a strong default for file transformation workflows, though pipeline can destroy participating streams on error, so an HTTP response may already be unusable for a fallback error body.

Go one level deeperFor a failed download, distinguish errors before headers are sent from errors after response streaming has begun.
Common trap: Do not assume a failed pipeline leaves the response socket available for a JSON error.
Reference: Node.js stream API Node.js backpressure guide
037How would you process a multi-gigabyte file?IntermediateDesignIllustrated
Interview answer

Use createReadStream and incremental parsing or transformation, with explicit limits on chunks, records, and downstream work. Avoid readFile when the whole file would exceed the memory budget. Handle malformed records and cancellation; a streaming parser should also cap a single oversized record.

Go one level deeperFor line-oriented text, discuss multibyte characters and chunk boundaries instead of assuming every chunk is a complete line.
Common trap: Calling split on a growing string buffer can recreate the same memory problem.
Reference: Node.js file system API Node.js Buffer documentation
038How do you resolve paths safely and locate files relative to an ESM module?IntermediateSecurity
Interview answer

Use new URL("./asset.txt", import.meta.url) for a module-relative file URL. In current Node.js, import.meta.dirname and filename are available for local file modules. For user-selected files, normalization alone is not authorization: constrain access to an approved root, validate containment correctly, and consider symlinks and race conditions.

Go one level deeperNever trust a request path merely because path.join or path.resolve produced a syntactically valid path.
Common trap: String prefix checks can confuse /safe and /safe-other and may miss symlink escapes.
Reference: Node.js ECMAScript modules Node.js path utilities OWASP Node.js security
039How should you use the built-in fetch API robustly?IntermediatePracticalIllustrated
Interview answer

fetch is built in and uses Undici. Check response.ok or status because an HTTP 404 or 500 normally fulfills the fetch Promise. Set an appropriate AbortSignal, consume or cancel the response body, validate expected data, and bound response size when the peer is untrusted.

Go one level deeperChoose retry behavior by operation semantics; a failed response does not prove the remote side performed no work.
Common trap: A fulfilled fetch Promise does not mean a successful HTTP status.
Reference: Node.js fetch with Undici Node.js global APIs
040When should you choose WebSockets instead of server-sent events?IntermediateComparisonIllustrated
Interview answer

WebSockets support bidirectional messaging over a long-lived connection. Server-sent events are well suited to text event updates flowing from server to client over HTTP. Modern Node.js has a built-in WebSocket client, but that alone is not a complete WebSocket server. Plan authentication, reconnects, heartbeat behavior, and fan-out across instances.

Go one level deeperFor notifications alone, compare operational simplicity before selecting a bidirectional protocol.
Common trap: An open connection is not a durable message queue.
Reference: Node.js built-in WebSocket client Node.js HTTP API WHATWG server-sent events specification
SECTION 05 / QUESTIONS 041-050

HTTP and Express

041What happens during a Node.js HTTP request?BeginnerConceptIllustrated
Interview answer

A server receives a request and exposes an IncomingMessage, which is readable, and a ServerResponse, which is writable. Your code inspects method, path, headers, and possibly a bounded body, then sends headers and finishes the response. The core HTTP layer is intentionally lower-level than Express.

Go one level deeperUse a URL parser, set content types deliberately, and define body, header, and time limits.
Common trap: Forgetting res.end or an equivalent framework response can leave a request hanging.
Reference: Node.js HTTP API
042What is Express middleware, and why does order matter?BeginnerConceptIllustrated
Interview answer

Middleware receives req, res, and next. It can enrich the request, send a response, or pass control onward. Registration order defines the pipeline: parsing, authentication, authorization, and handlers must be arranged intentionally. A middleware that neither responds nor calls next leaves the request pending.

Go one level deeperPut a signature-verifying raw-body webhook route before incompatible JSON parsing middleware when required by the provider.
Common trap: Calling next after sending a response can let later code attempt a second response.
Reference: Express middleware guide Stripe webhook delivery and duplicate events
043What changed about asynchronous error handling in Express 5?IntermediateCurrent knowledgeIllustrated
Interview answer

Express 5 automatically forwards a rejection from a Promise returned by a route or middleware to error handling. An async function returns such a Promise. Detached work, forgotten return values, and unrelated timer callbacks still need explicit error routing or their own lifecycle management.

Go one level deeperDuring migration from Express 4, check both error wrappers and route syntax changes against the migration guide.
Common trap: Express cannot catch a Promise it was never given merely because that Promise was created inside a handler.
Reference: Express 5 migration guide Express error handling
044How do you implement centralized Express error handling?IntermediatePracticalIllustrated
Interview answer

Register an error middleware with four parameters, (err, req, res, next), after routes. Map known application errors to intentional statuses, log a correlation identifier, and return a safe error shape without stack traces or secrets. If headers were already sent, delegate with next(err) rather than sending another body.

Go one level deeperSeparate trusted application error codes from arbitrary error messages coming from a dependency.
Common trap: A three-argument middleware is not an Express error handler.
Reference: Express error handling OWASP REST security
045What do safe and idempotent mean for HTTP methods?IntermediateComparison
Interview answer

A safe method is intended not to change application state. An idempotent method has the same intended server effect when the same request is repeated. GET is safe and idempotent; PUT and DELETE are idempotent by defined semantics, but not safe. POST and PATCH are not automatically idempotent.

Go one level deeperA second DELETE can return a different status while still having the same intended final state.
Common trap: Idempotent does not mean every response must be identical.
Reference: HTTP semantics: RFC 9110
046Which HTTP status codes should an API developer explain?BeginnerPractical
Interview answer

Use 201 for a created resource, 204 for success without a response body, 400 for a bad request, 401 for missing or invalid authentication, 403 for refused access, 404 for absence, 409 for a state conflict, 429 for rate limiting, and appropriate 5xx statuses for server or upstream failures. Document the error contract.

Go one level deeperA 401 response normally includes a suitable WWW-Authenticate challenge. Avoid leaking resource existence where policy requires concealment.
Common trap: A 204 response must not include an application response body.
Reference: HTTP semantics: RFC 9110 OWASP REST security
047Where should request validation happen?IntermediateSecurityIllustrated
Interview answer

Validate at the boundary before business logic uses the input. Parse content intentionally; constrain body size, permitted fields, types, ranges, and formats; and enforce business invariants in the service and data layers. Authentication proves identity, authorization permits an action, and validation checks data; all three are needed.

Go one level deeperValidate uploaded files by more than the extension or claimed content type, and never store them at user-chosen executable paths.
Common trap: Rejecting malformed JSON alone does not validate a business request.
Reference: OWASP input validation OWASP Node.js security
048How do offset and cursor pagination differ?IntermediateDesign
Interview answer

Offset pagination is simple but can become costly for deep pages and can shift when rows are inserted or removed. Cursor/keyset pagination continues from a stable ordered key, often a tuple such as created_at and id. Use a deterministic order, an appropriate index, bounded page sizes, and validated cursors.

Go one level deeperExplain what happens when sort values tie and whether the API promises a consistent snapshot across pages.
Common trap: Ordering only by a non-unique timestamp can skip or repeat rows.
Reference: PostgreSQL LIMIT and OFFSET PostgreSQL indexes
049What is CORS, and what does it not protect?IntermediateSecurityIllustrated
Interview answer

CORS communicates which browser origins may read a response using browser-enforced cross-origin rules. It is not authentication or authorization and does not stop a direct server-side client from calling an endpoint. Configure allowed origins and credentials deliberately; a credentialed browser request cannot use a wildcard allowed origin.

Go one level deeperReason about CSRF separately: preventing a script from reading a response does not mean every request is prevented.
Common trap: "CORS enabled" does not mean "API secured."
Reference: Express CORS documentation OWASP CSRF prevention
050How should rate limiting work across multiple Node.js instances?AdvancedDesignIllustrated
Interview answer

Choose an identity and a policy, such as a token bucket or sliding window, then enforce shared limits using atomic operations in a suitable shared store or gateway. Bound bursts and response costs, return useful retry guidance, and define fail-open or fail-closed behavior. Trust proxy headers only from known infrastructure.

Go one level deeperAn IP-only rule may penalize shared networks and miss authenticated account abuse; combine dimensions thoughtfully.
Common trap: Separate in-memory counters on each replica do not implement one strict global limit.
Reference: Express production security OWASP REST security

095Implement a concurrency-limited async map with ordered results.AdvancedCodingIllustrated
Interview answer

The implementation below starts at most limit mapper calls at once and stores each result by its original index. On the first observed failure it stops taking new work, waits for already-started work to settle, and throws that failure. It accepts a cooperative AbortSignal. The input and results are arrays, so total storage remains O(n).

export async function mapLimit(items, limit, mapper, { signal } = {}) {
  if (!Array.isArray(items)) throw new TypeError('items must be an array');
  if (!Number.isInteger(limit) || limit < 1) {
    throw new RangeError('limit must be a positive integer');
  }
  if (typeof mapper !== 'function') throw new TypeError('mapper must be a function');
  signal?.throwIfAborted();
  const results = new Array(items.length);
  let next = 0;
  let failed = false;
  let firstError;

  async function consume() {
    while (!failed) {
      try {
        signal?.throwIfAborted();
        const index = next++;
        if (index >= items.length) return;
        results[index] = await mapper(items[index], index, signal);
      } catch (error) {
        if (!failed) { failed = true; firstError = error; }
        return;
      }
    }
  }

  await Promise.all(Array.from(
    { length: Math.min(limit, items.length) }, () => consume()
  ));
  if (failed) throw firstError;
  return results;
}

098Write a small HTTP health endpoint without Express.IntermediateCodingIllustrated
Interview answer

The example constructs a server with GET and HEAD /health, returns JSON for GET, sends no body for HEAD, and handles missing routes and unsupported methods. A factory keeps it easy to test on an ephemeral port. Production use also needs deliberate timeouts, health semantics, logging, and graceful shutdown.

import { createServer } from 'node:http';

export function createAppServer() {
  return createServer((req, res) => {
    let path;
    try { path = new URL(req.url ?? '/', 'http://localhost').pathname; }
    catch { res.writeHead(400).end(); return; }
    if (path !== '/health') { res.writeHead(404).end(); return; }
    if (req.method !== 'GET' && req.method !== 'HEAD') {
      res.writeHead(405, { Allow: 'GET, HEAD' }).end();
      return;
    }
    const body = JSON.stringify({ status: 'ok' });
    res.writeHead(200, {
      'Content-Type': 'application/json; charset=utf-8',
      'Content-Length': Buffer.byteLength(body)
    });
    res.end(req.method === 'HEAD' ? undefined : body);
  });
}
